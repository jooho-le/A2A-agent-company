# 114. 서비스 검증 질문 대기와 답변 화면 수정

작성일: 2026-11-26.

## 실제 원인

Run `00e8418f-3bbb-4fc5-a8a8-c633058811b1`에서 QA는 `QA_INPUT_REQUIRED` 질문을 남기고 기다렸지만, Security 완료 후 전체 Run은 `FINISHED / UNVERIFIED`로 종료됐다. 사용자가 입력한 답변은 종료된 Run에 대한 요청으로 409 거절됐다.

Host는 무인 실험을 위한 자동 종료 규칙을 서비스의 QA 질문에도 적용하고 있었다. 질문 조회 API와 프론트는 Run의 종료 여부보다 과거 Step의 입력 대기를 우선해, 실행할 수 없는 ‘답변하고 이어가기’ 버튼을 보여줬다. 새로고침이나 답변 내용으로 해결할 수 있는 문제가 아니었다.

## 수정 내용

- `SERVICE-WEB`에서 QA·Security의 일반 확인 질문은 자동 종료보다 대기를 우선한다. Run은 기존 상태 전이 규격에 따라 `HUMAN_REVIEW`로 이동하고 `VALIDATING` 또는 `REVALIDATING`을 재개 상태로 보관한다. 새로운 상태나 전이 경로는 만들지 않는다.
- 기존 Task·Context·Step, 완료된 동료 Agent의 결과를 보존한다. 이후 답변은 기존 제어 경로로 특정 질문에만 전달하고, 완료된 동료는 다시 실행하지 않는다.
- `SCN-001` 무인 비교 실험의 자동 종료 정책과 실제 실패·증거 검증 규칙은 유지한다. 의미 검토 실패를 일반 질문으로 바꿔서 성공 처리하지 않는다.
- 질문 조회는 Run이 실제 대기 중일 때만 질문을 반환한다. 종료됐거나 아직 실행 중인 Run의 과거 질문을 답변 대상으로 노출하지 않는다.
- 프론트는 Run 조회와 질문 조회 중 어느 쪽에 종료 상태가 먼저 도착하더라도 답변 폼·확인 대기 안내를 숨긴다.
- 답변이 409로 거절되면 질문 정보와 상위 Run 정보를 갱신한다. 자동 재전송 없이 입력 초안은 유지하며, 종료된 경우 ‘이미 종료됐어요’라고 안내한다.

종료된 기존 Run을 다시 열거나 기록을 변경하지 않았다. 동결된 요구사항을 답변만으로 변경하거나, 인증·승인·예산·중복 방지 검사를 우회하지 않는다.

2. 기존 자동 종료·작업 제어 제한·재검증 Context: 57개.
3. QA 답변 후 완료된 Security 보존, Security 답변 후 완료된 QA 보존, QA 재검증 답변 시 Source·수정 회차·기존 예산 보존: 3개.

모델·Docker를 대체한 격리 검사이며 실제 OpenAI 호출이나 생성 코드 실행 결과를 의미하지 않는다.

임시 Chrome 프로필의 실제 프론트 컴포넌트·Hook 검사 1개에서 다음 **6가지 시나리오 통과**:

- 질문 표시·특정 직원에게 답변 한 번 전달.
- 응답 유실 시 접수 조회로 복구하고 POST를 반복하지 않음.
- 직원 전환과 질문 도착 때 초안 보존.
- 확인 후 한 번만 작업 중단 요청.
- 답변 직전 종료된 경우 409 처리·상태 갱신·재전송 차단·초안 보존.
- 두 조회의 도착 순서가 달라도 종료된 작업의 답변 버튼 숨김.

`npm run lint`, `npm run build`, `git diff --check` 통과. 빌드에는 기존 3D 번들의 크기 경고가 남는다. Python 검사에서는 SDK의 cross-replica streaming 비활성 경고가 발생했다.

## 로컬 적용과 다음 확인

실행 중인 작업이 없음을 확인한 후 Host와 Agent 4개를 정상 재시작했다. 제품 서버와 프론트는 유지했다. 적용 후 읽기 전용 조회 결과:

| 확인 항목 | 결과 |
| --- | --- |
| Host·제품·프론트 연결 | HTTP 200 |
| 승인 Configuration 조회 | HTTP 200 |
| 인증 없는 Host 조회 | HTTP 401 유지 |
| 기존 실패 Run의 질문 조회 | `FINISHED`, `requests: []`, `canCancel: false` |

새 AI 작업이나 사용자 답변 재전송은 실행하지 않았다. 실제 API를 통한 새 서비스 작업의 대기·답변·최종 검사 완료는 사용자의 다음 실행에서 확인해야 한다.

사용자는 브라우저를 `⌘ + Shift + R`로 새로고침한 뒤, 다시 시험할 때 ‘새 작업 만들기’로 시작하면 된다. 이미 종료된 기존 작업은 답변으로 재개할 수 없다.
