# 실제 서비스 연결 점검

## 점검 범위

공개 오피스 → 로그인·프로젝트 → 승인 설정 조회 → 업무 접수 → Run·Step·Trace 표시 → 접수 장애 복구를 점검했다. 백엔드·Host·역할별 Agent의 실제 HTTP 응답, 브라우저 렌더링, 관련 자동 테스트와 플랫폼 회귀 검사를 구분했다. 유료 OpenAI Run은 생성하지 않았다.

## 발견하고 수정한 부분

| 문제 | 수정 |
| --- | --- |
| 승인 조회 단계의 503도 전송 불명으로 처리하여 접수 대기에서 빠져나올 수 없음 | 서버가 Host POST 전 미접수를 확정한 경우만 전용 헤더를 반환. 일반 503과 구분하고 명시적 재접수 허용 |
| 승인 설정 변경 409 후 이전 설정으로 계속 요청 | 승인 설정을 무효화하고 서버 연결·설정 재조회 버튼 제공 |
| 재로그인 시 미확인 접수 ID를 잃거나 다른 계정에 복구 상태가 이어질 위험 | 계정별 세션 키에 요청 UUID만 저장. 이전 버전의 ID도 보존·이관하고 서버 인증·소유권 검증 후 GET으로 복구 |
| REJECTED도 버튼에 접수됨으로 표시 | CREATED만 접수됨으로 표시하고 거절된 요청은 수정·재제출 가능 |
| Host 응답의 잘못된 Run 구조·타입이 500으로 이어질 수 있음 | UNKNOWN 유지, ProjectRun 연결 차단. NaN·Infinity 같은 비표준 JSON도 차단 |
| 시나리오 레지스트리를 읽지 못하면 승인·접수에서 500 발생 | 상세 경로를 공개하지 않고 503으로 차단, Host 호출·접수 생성 없음 |
| 취소된 프로젝트 복원 요청을 화면 오류로 표시 | AbortError 무시, 새 업무를 열면 이전 복원 오류 제거 |
| 제거한 시연 로직의 미사용 코드 및 테스트의 React 렌더 부작용 | 사용하지 않는 변수·함수 삭제, 테스트 관측을 Effect로 이동. ESLint 오류·경고 해소 |

기존 사용자 데이터·인증 설정·A2A 계약·에이전트 역할·예산과 재시도 정책은 변경하지 않았다. 유효한 미확인 접수는 임의로 취소하거나 다른 키로 자동 재생성하지 않는다.

플랫폼 회귀 검사의 개발 패키지는 프로젝트 환경을 변경하지 않도록 임시 검사 환경에 구성했다. 부모 pytest에만 설정된 경로를 자식 프로세스가 찾지 못한 초기 실패는 검사 환경을 보정한 뒤 다시 확인했다.

최종 집계는 모듈별 검사 묶음을 합산했다. 평가 관련 85개 통과, 먼저 완료한 모듈 4,296개는 4,279개 통과·14개 미실행·3개 실패였으며 이 중 환경 문제 2개는 보정 후 재검사 통과했다. 나머지 1,397개는 최대 4개의 Python 테스트 프로세스로 실행하여 전부 통과했다. AI 에이전트에 작업을 위임하거나 실제 OpenAI Run을 생성한 검사가 아니다. SDK의 이벤트 스트림 미설정·일부 폐기 예정 API 안내 등 기존 pytest 경고도 있었으며, ESLint 경고와는 별개다.

## 실제 실행과 구분할 부분

- Docker Desktop이 꺼져 있어 백그라운드로 실행했다. 데몬 29.9.3과 승인된 linux/arm64 이미지를 확인했다. 시작 커밋·의존성 잠금 해시가 승인 설정과 일치했고, 네트워크 차단·읽기 전용·일반 사용자 컨테이너에서 FastAPI/SQLAlchemy/Argon2/Uvicorn 로딩을 확인했다.
- 실제 OpenAI 코드 생성 → Docker Build → QA/Security → 최종 SUCCESS를 끝까지 수행한 검사는 아니다. UI·API·회귀 테스트 통과를 실제 생성 결과의 성공으로 해석하지 않는다.
- 현재 지원 시나리오는 SCN-001 회원가입이다. 제품용 소스 ZIP 다운로드 중계는 기존 연결 작업의 범위에 포함되지 않았다.
- 프론트 5173과 제품 API 8000을 실행했으며 기존 Host 8002·Agent 8101~8104를 유지했다. Git commit/push는 수행하지 않았다.

## 남은 별도 평가기 이슈

재현 대상: tests/evaluation/test_security_limits.py의 test_case_finishes_in_time_with_the_expected_outcome[one password repeated 3000 times]. 같은 password 표현식을 3,000번 연결한 소스에서 현재 Python 3.11.9의 ast.parse가 RecursionError를 반환한다. 평가기는 종료되고 REQ-003·005·006을 UNVERIFIED로 남기지만, 해당 테스트는 PASS를 기대하여 실패한다. 단독 실행에서도 재현했다.

이 항목은 프론트/API 접수 오류와 별개인 평가기 분석 한도·시험 기대값의 불일치다. 생성물의 안전성을 임의로 통과시키지 않으며 현재 검증 불가로 처리한다. 평가 담당에서 지원할 코드 복잡도와 실패 시 판정 기준을 맞춰야 한다. 이번 점검에서 평가기 소스와 테스트 기대값은 변경하지 않았다.
