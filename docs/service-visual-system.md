# 서비스 전체 오피스 디자인 적용

## 적용 범위

| 화면 | 변경 내용 |
| --- | --- |
| 공통 | 기존 검정·파랑·라임색, 고정 메뉴 위치를 유지하고 글라스 표면·얇은 선·큰 제목·둥근 버튼을 공유한다. |
| 프로젝트 | 검색창과 프로젝트 카드를 정리하고, 목록·빈 화면·오류 안내의 간격을 맞췄다. |
| 우리 직원 | 기존 캐릭터 5명을 먼저 보여주고 협업 관계 설명을 아래에 배치했다. 역할별 색감과 리더 구분은 유지한다. |
| 업무 흐름 | 실제 직원 상태와 수신한 Trace를 별도 영역으로 보여준다. 업무가 없으면 시작 안내를 표시한다. |
| 결과물 | 산출물 카드·등록 정보·빈 화면을 같은 표면으로 정리했다. |
| 직원·프로젝트 상세 | 네이티브 dialog를 유지하고 글라스 배경·본문 여백·닫기 버튼·긴 식별자의 줄바꿈을 맞췄다. |
| 로그인·회원가입 | 전체 오피스 배경 위 중앙에 글라스 인증 카드를 팝업처럼 띄운다. 기존 직원 캐릭터는 주변에 배치하고 인증 처리는 유지한다. |
| 전자문서·별도 Run 조회 | 기존 업로드·조회 구조 위에 공통 입력·버튼·카드·제목 스타일을 적용했다. |

## 공통 규칙

- `frontend/src/ServiceTheme.css`에서 색상, 글라스, 테두리, 라운드를 관리한다. 카드 28px, 입력 14px, 버튼·검색창은 pill 형태다.
- `design/DESIGN.md`의 큰 타이포그래피와 검은 전시 공간 구성을 참고한다. 제품의 기존 색상과 오피스 이미지는 유지한다.
- 오피스는 실제 3D 장면을 사용하고, 다른 페이지에는 같은 오피스의 정적인 배경을 어둡게 깐다. 다른 페이지에서 추가 3D 렌더러를 실행하지 않는다.
- 모션 줄이기 설정을 따르고, 등장 애니메이션이 끝나면 transform과 opacity를 남기지 않아 배경 흐림이 정상 작동하도록 한다.
- API, 인증, 제출·재시도, 프로젝트 복원, Run 상태 판단, 데이터 저장 코드는 변경하지 않았다. `WorkflowRunView`는 기존 조회 결과를 표시하는 컴포넌트다.

## 검증과 범위

- 후속 사용성 정리까지 프론트 테스트 197개, 빌드, ESLint 통과. 기존 3D 번들의 500KB 초과 안내는 남아 있다.
- 임시 Chrome 프로필과 브라우저 내부의 조회용 데이터로 프로젝트·직원·업무 흐름·결과물·전자문서·로그인·회원가입을 렌더링했다. 데스크톱과 390px 모바일에서 가로 넘침·깨진 이미지·런타임 예외가 없었다.
- 프로젝트 및 직원 상세 팝업의 열기·닫기, Escape, 로그인 비밀번호 표시, 로그인↔회원가입, 오피스 복귀와 모바일 메뉴 이동을 확인했다.
- 로그인·회원가입은 화면을 좌우로 나누지 않는 기존 중앙 배치로 복원했다. 작은 화면에서는 장식을 줄이고 입력과 화면 스크롤을 우선한다. 시각적으로 팝업 형태이며 기존 인증 페이지의 전환 구조를 사용한다.
- 별도로 제공한 상태·이벤트 데이터로 업무 타임라인의 직원 4명과 전달 기록 3개를 렌더링했다. 타임라인 및 별도 Run 조회 화면의 320px 가로 넘침도 확인했다.
- 시각 점검 데이터는 제품 코드나 저장소에 추가하지 않았다. 실제 계정 생성, 문서 업로드, AI 업무 실행 및 유료 API 호출은 이번 점검에 포함하지 않는다.
- 디자인 참고용 HTML·발표 자료·백엔드는 수정하지 않았다. Git commit/push는 수행하지 않았다.

사용성 후속 변경은 [쉬운 사용 흐름](simple-service-ux.md)에 정리했다. 주요 메뉴와 제목을 줄이고 기술 정보는 접어두며, 로그인과 다음 행동을 바로 선택할 수 있게 했다.
