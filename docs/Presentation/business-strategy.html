3. 고객이 Codex·Claude 대신 또는 함께 우리 제품을 쓸 이유

3-1. 제품 경험 차별화 후보 (아직 검증되지 않음)

  1. 역할별 에이전트와 도구를 직접 구축하지 않음: 미리 정의된 PM→개발→QA/Security→수정 워크플로.
  2. PM 역할 공백 보완: 고객 요청을 요구사항 ID, 범위, 인수 기준으로 정리하고 개발자/고객 승인 흐름 관리.
  3. 검증 결과가 수정 작업과 연결: 단순 “테스트 FAIL”이 아니라 관련 Snapshot·수정 작업·재검증 기록을 연결.
  4. 납품·인수 근거 일괄 생성: 코드/PR, 실제 Build/테스트/보안 결과, 수정 이력, 미검증 사항.
  5. 투명한 실행 비용과 예산 상한: 사용자 직접 멀티 에이전트 설정 대비 비용 예측 및 제한.
  6. 역할별 모델 선택: 단순 업무는 저가 모델·규칙 기반 도구, 복잡한 코딩만 고성능 모델.

구매를 설득할 기준: 동일 고객 요구에 대해 기존 Codex·Claude Code + GitHub/CI 워크플로 대비 동일하거나 더 나은 검수 가능한 품질에서 총 처리비용 및 사람의 조율시간이 실제로 감소해야 한다.

3-2. AI Project Manager (차별화의 중심 UX)

  • PM/대표: 고객 요청과 완료 기준을 입력하고 승인 대상·상태·예산을 확인
  • Developer: 코드 변경/PR, 수정 대상과 이전 FAIL 근거를 확인
  • QA/Security: 실제 테스트/스캔 실행 및 결과 확인
  • 고객: 인수용 보고서로 요구사항별 완료/미완료·미검증을 확인
  • Orchestrator: A2A Task·Artifact·Snapshot·재시도·비용 및 사람 승인 대기 상태 관리

MVP에서는 지원 기술 스택 하나와 비민감 예시 프로젝트에 집중한다. 기업 권한, 고객 포털, Git/PR 통합, 청구 기능은 개발 계획이며 기존 캡스톤 구현과 혼동하지 않는다.

하나의 '사이트 1개' 또는 '앱 1개'는 비용 단위가 아니다. 기능 수·기술 스택·요구 수정·실행 횟수에 따라 비용이 급증한다. 아래는 하나의 지원 스택에서 생성+테스트+일부 수정까지 수행하는 경계가 정해진 과제의 예시다.

상품화 시나리오포함 범위제외/한계

B. 일반 웹서비스로그인, 간단한 DB CRUD, 관리자 목록·검색, 기능 테스트, 제한된 수정대규모 권한·실운영 보안 보증·외부 결제 제외

가정한 사용량은 모든 Agent 호출 + 오류 수정 루프를 합친 양이다. 실제 서비스 완성을 보증하는 데이터가 아니며, 실행 정책에 따라 크게 달라질 수 있다.

6. 수익모델 개정 — B2B SaaS 월 구독 + 포함 크레딧 + 추가 사용량

v06에서 선택한 기본 구조: 월 구독료를 받고 프로젝트/요구사항 관리 및 Planner·Developer·QA·Security 실행 환경을 제공한다. 구독료에는 정해진 작업 크레딧이 포함되며, 초과 작업은 고객이 사전 동의 후 추가 크레딧을 구매한다. 무제한 고정요금도, 토큰 1개마다 실비를 그대로 청구하는 순수 종량제도 주력으로 선택하지 않는다.

6-1. 순수 SaaS 정액 vs 하이브리드: 왜 후자를 선택하나?

관점순수 월 정액(무제한)월 구독 + 크레딧(선택)
고객의 예산 예측단순함구독료·포함량·추가 상한 제시로 통제 가능

매출 예측구독료가 고정구독료에 더해 사용량 증가 시 매출 확장

  • 기본료 가치: 요구사항·검수 기준/프로젝트 이력, 역할별 AI 개발 워크플로, 사용량·예산 대시보드, 코드·테스트·보안 결과 관리. 구체 기능은 출시 시 구현 검증 필요.
  • 사용량 차단: 크레딧 소진 시 실행 일시정지 또는 명시적 추가 구매. 자동 초과 결제 OFF가 기본값.
  • 크레딧의 소멸·이월/환불·실패차감: 아직 미정. 고객이 알기 쉬운 약관과 실측 원가를 바탕으로 정해야 한다.

6-3. 작업 종류별 예상 차감표 — 범위 확인 전 확정 견적 금지

중요한 원가 해석: 0.5/1/4 크레딧은 정책 가설이며 단순히 API 사용량으로 직접 비례한 숫자가 아니다. 예를 들어 4크레딧 MVP는 원가 33,500원으로 추정되지만 추가 지원·재시도 위험이 커서 가격·차감 기준을 실측 후 재설계해야 한다. 1크레딧짜리 웹서비스도 프로젝트 복잡도가 높으면 2~3크레딧 이상 필요할 수 있다.

단건 참고가격은 유지: v05의 랜딩페이지 19,900원 / 웹서비스 79,000원 / 웹 MVP 199,000원은 고객의 작업별 지불의사 비교에 쓰는 참고가격/단건 파일럿 후보다. v06의 메인 상품은 위 구독+크레딧이고, 단건 가격을 상시 별도 상품으로 동시 판매한다고 확정한 것은 아니다.

6-4. 월간 손익 시뮬레이션 — 포함 크레딧을 전부 썼을 때

계산 전제: 내부 간편 비교를 위해 표준 크레딧당 계획 자동화 변동원가 11,000원을 적용한다. 이는 v05 B 웹서비스 추정치에 기반한 가상 평균이며, 모든 고객·작업에 일괄 적용할 실제 원가는 아니다.

주의: 위의 잔여액은 순이익도 완전한 공헌이익도 아니다. 고객지원/사람 검수시간을 추가하면 특히 Lite는 역마진이 될 수 있다. 추가 크레딧도 같은 원가 11,000원이라는 임시 가정이면, 판매가 19,900원에서 추가 고객지원·결제비 차감 전 8,900원이 남는다. 난도가 높아져 실원가가 19,900원을 넘으면 해당 크레딧 가격은 유지할 수 없다.

6-5. 한도가 있는 월 구독의 고객 경험

  1. 팀이 Core 월 99,000원에 가입하고 5크레딧을 받음.
  2. “작은 관리자 기능 구현” 요청을 입력하면 시스템이 예상 1크레딧/지원 범위를 먼저 표시.
  3. 승인 후 실행; 모델·도구·재시도 사용량은 내부적으로 기록.
  4. QA/보안 도구 검사 및 코드 수정은 계약된 수정 횟수·크레딧 예산 안에서 수행.
  5. 추가 범위·초과량이 예상되면 실행 전 정지 → 사용자 동의 → 추가 크레딧 구매 또는 작업 축소.
  6. 플랫폼 귀책 실행 실패, 고객 요구 변경, AI 품질 미달을 구분하여 공정한 크레딧 반환·추가 청구 규칙 적용.

필수 보호장치: 추정 크레딧과 실제 사용 크레딧을 사전 공개, 사용량 알림(예: 80%), 하드 상한, 도구 장애 환급 정책, 카드 자동 추가결제 기본 비활성화.

6-6. 고객 비용 우위: Codex·Claude Code와 동등 조건 비교

고객이 이미 Codex·Claude Code를 월 구독으로 쓰고 있다면 우리 제품은 추가 비용이다. 정액 구독료와 API 토큰 단가를 곧바로 비교해서 '우리 것이 저렴하다'고 말하면 안 된다.

기존 고객 총비용 = 기존 도구의 증분 결제비 + 도구/서버비 + 기존 방식의 PM·QA·수정·납품 사람시간 가치.

우리 도입 후 총비용 = 우리 월 구독료 + 추가 크레딧 + 도구/서버비 + 사람 승인·추가 검수·온보딩 시간 가치 + 남아 있는 기존 도구비.

가상 ROI 예: 기존에 요청 1건당 사람 조율·검수시간 3시간, 우리 제품에서는 1.5시간, 사람시간 가치 30,000원/시간이면 건당 45,000원 상당의 시간 기회비용 절약. 월 5건이면 225,000원 상당. Core 월 99,000원 구독비를 뺀 126,000원 상당의 계산상 여유가 있지만, 이는 인건비 현금절감 보장이 아니며 구현 품질·온보딩·추가 검수·실패·초과 크레딧 비용을 제외한 값이다.

최종 가격 우위 검증: 같은 고객 과제를 같은 품질/인수 기준으로 완료했을 때 구독료와 사람의 개입·재작업까지 포함한 총비용이 더 낮아지는지 실측한다.

6-7. 첫 판매의 순서 — 파일럿 → 구독

  • 초기 유료 파일럿: 비민감·범위 제한된 실제 기능 변경 1~3건에 대해 건별 또는 짧은 기간형 견적. 기존 v04의 30만~100만 원 / 2~4주는 실험 후보로만 보존하며 필수 판매가격이 아님.
  • 파일럿 성공 후: 반복 작업량과 크레딧 사용 패턴을 확인하고 Team Core 등 정기 구독 제안.
  • 확대: 같은 팀의 추가 프로젝트/개발자/고객 요청에서 크레딧 재구매·상위 플랜 전환.
  • B2C 단건 판매: 초기 B2B 검증을 분산시키므로 주력 GTM에서 제외.

13. 최종 사업 정의

초기 고객: Codex·Claude Code 등을 이미 사용하지만 PM·QA 전담자가 없는 2~5인 외주·개발팀.

문제: 코드를 쓰는 것 외에도 고객 요구사항 정리, 테스트, 수정 지시, 프로젝트 납품·검수에 사람이 계속 필요하다.

해결: A2A 기반 역할별 Agent와 기존 검사 도구로 이 업무를 정해진 프로세스 안에서 처리하고, 인수 증거와 사람 승인 경로를 제공한다.

경쟁 우위 가설: 고성능 모델을 모든 작업에 반복 투입하지 않고, 모델 라우팅·최소 문맥·결정적 도구·선택적 재검증으로 같은 품질의 업무를 낮은 총비용으로 끝낸다. 현시점 입증 전.

수익: 범위 제한 작업별 실행권 → 반복 고객용 월 구독 + 포함 작업 크레딧 + 사용자 승인형 추가 크레딧 구매 → 팀/프로젝트 확장. 단건 가격은 크레딧 산정의 참고자료로 유지.

PMF: 실제 절감된 사람시간 + 동일 품질 + 고객 실결제 + 재구매/갱신 + 양의 공헌이익.

GTM: 30개 초소형 개발팀 선별 → 10곳의 기존 Codex 업무 파악 → 5건 비교 데모 → 2팀 유료 파일럿 목표.

결론: “또 하나의 코딩 에이전트를 파는 것이 아니라, PM·QA 인력이 부족한 작은 개발팀이 기존 도구를 직접 조립하지 않고도 개발·수정·검증을 수행하도록 하며, 완수 품질 대비 총업무비용을 낮추는 AI 개발 협업 플랫폼을 지향한다.”
