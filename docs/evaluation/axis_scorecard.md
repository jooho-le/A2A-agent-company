# Run별 다섯 축 채점지

갱신: 2026-11-15 · 구현: `src/evaluation/axis_scorecard.py` · 저장 경로: `evaluation.workflow`

채점된 Run 결과 폴더에는 요구사항별 `summary.md`, 세부 항목별 `check_details.md`·`.json`, 다섯 축별 `axis_scorecard.md`·`.json`을 함께 저장한다. 축별 채점지는 기존 평가·측정 결과를 모아 보여주며 추가 모델 호출이나 시험 실행을 하지 않는다. 생성물 없이 끝난 미채점 Run도 축별 채점지를 남기고, 사람 보조 재개로 격리한 Run에는 생성하지 않는다.

## 축별 출처와 해석

| 축 | 기존 결과·기록 | 표시 내용 |
|---|---|---|
| 정확도 | 독립 평가 보고서, 채점 결과, Run 기록 검사 | 요구사항 완전 충족률, 제품 시험 통과, 보안 검사, 판정 가능률, 기록 노출·추적 범위 |
| 속도 | Run 사건 지표, 결과 패키지 시각, 버전별 채점 시각 | 판정·패키지 완료·첫 빌드·보존 Snapshot 최초 통과·종료까지 시간, 사람 대기 |
| 비용 | 사용량·단가 적용 결과, 의미 검토 호출 기록 | 모델/도구 호출, 입력·출력 토큰, API 비용, 완전성, 의미 검토 호출 |
| 과정 | 과정 지표, Agent 평가표, 회귀 결과, Run 기록 검사 | 수정 경로, 재시도·관문 거부, 관찰된 오류 지점, 회귀 후보, 전달·노출·충돌 |
| 안정성 | Run 종료 분류, 자동 완료 기록, 제품 판정 | 제품 통과·자동 완료의 분자 포함 여부, 미검증·중단·멈춤·사람 보조 재개 |

ACC-01은 **7개 요구사항 중 연결된 필수 검사가 모두 PASS인 요구사항의 비율**이며 미검증을 반영한 하한·상한을 표시한다. 요구사항별 부분점수 평균은 보조 지표다. REQ-003의 세 검사 중 SEC-003만 FAIL이면 ACC-01은 6/7(약 0.857), 부분점수는 약 0.952이므로 같은 값으로 읽지 않는다. ACC-02 제품 통과에는 공식 검사 9개가 모두 PASS여야 한다. 코드 모양이나 줄 수는 정확도 점수가 아니다.

## 값이 없거나 Run을 채점하지 못한 경우

- `MEASURED`: 기존 근거로 측정·판정한 값. `false`도 확인된 결과다.
- `UNVERIFIED`: 자료 누락·불완전으로 미확인. 값은 null과 사유로 남기며 0으로 채우지 않는다.
- `GROUP_ONLY`: 계획 Run 전체를 이용하는 비교 지표. TIME-04, COST-03, STAB 비율·분포·변동은 `comparison.md`에서 계산한다.

미채점 Run은 정확도를 미확인으로 남기고 제품 통과 분자에는 넣지 않는다. 남아 있는 시간·사용량·안정성 자료는 보존한다. 보존한 모든 Snapshot을 검사해 통과한 버전이 없다고 확인한 TIME-05는 ‘통과한 버전 없음’이며 자료가 없어 모르는 경우와 구분한다.

단계 기록이 없으면 오류 없음을 추정하지 않는다(`NO_OBSERVED_STEPS`). 기록된 단계에 문제가 없을 때도 ‘기록된 단계에서 오류 미발견’으로 범위를 표시한다. 토큰 구분 완료 표시만 있고 실제 입력·출력 토큰 값이 없으면 `USAGE_INCOMPLETE`, Run 상태가 없으면 `STABILITY_STATE_NOT_RECORDED`로 미확인 처리한다.
