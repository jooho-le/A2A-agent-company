# 92. QA 탐색 충돌과 에이전트 품질·수정 복구 경로 보완

작성일: 2026-11-23. 범위: 1·2번 담당의 Host, 역할 실행기, 공통 교정, SCN-001 비교 실행 설정. 사용자 요청에 따라 코드와 회귀 테스트만 수정했으며 모델·서버·Docker·테스트는 실행하지 않았다.

## 수정 배경

91번 40회 실행의 최종 고정 소스와 평가 기록에서 실제 결함이 확인된 실행은 30회, 평가 없음 또는 미확정은 8회, 독립 최종 9개 시험을 모두 통과한 제품은 2회였다. Host SUCCESS는 0회였다. 제품 결함과 검증 산출물 작성 실패를 분리해서 고친다.

통과 제품의 최종 중단 원인도 구분한다. Single Ver2 9회차의 최종 원인은 `QA_REPORT_BINDING_INVALID`, Multi Ver1 10회차는 필수 브라우저 시험 파일 누락에 따른 `QA_DRAFT_CORRECTIONS_EXHAUSTED`였다. 과거 교정 오류가 있었다는 사실만으로 두 실행의 최종 원인을 동일하게 해석하지 않는다.

### 공개 요구사항 Source 검사

`signup_quality_precheck`는 동결 SCN-001 계약에 연결한다. Source의 로컬 import 그래프만 최대 64개 파일·파일당 128KB·전체 1MB·AST 50,000노드까지 읽는다. 생성된 앱을 import하거나 실행하지 않는다.

다음은 확정 취약점이나 시험 결과가 아니라 **완료 전 코드 검토 경고**다.

- 기본 검증 오류에 입력을 포함할 수 있는 일반 문자열 비밀번호 모델. 모델·라우터 분리 시에도 점검한다.
- 오류 처리기가 있지만 응답으로 원시 `exc.errors()` 또는 예외 문자열을 전달하는 경로.
- 예외 객체·상세 추적을 로깅하는 경로. 한 모듈의 다른 로거 필터가 전체 로그 검사를 끄지는 않는다.
- 공백 제거가 필요한 공개 정책인데 원시 `payload.email`을 먼저 형식 검사하는 경로.
- 사전 중복 조회 후 commit 충돌을 포괄 예외에서 500으로 처리하고 별도 중복 거절 경로가 없는 경우.

모델에는 상대 Source 경로·줄 번호·공개 요구사항 키·정해진 경고 코드만 제공한다. 원시 예외, 비밀번호·해시, 보호시험 입력은 제공하지 않는다. 동적 앱 구성이나 분석할 수 없는 구현은 실행 검증을 대신하지 않는다. 경고 없음은 PASS가 아니다.

실제 생성 앱의 동작을 자동으로 정답 구현으로 치환하지 않는다. Developer가 공개 계약에 맞춰 수정하고, 이후 Build·QA·Security의 실제 측정으로 판단하는 책임 경계를 유지한다.

### Source 편집 복구

`WRITE_CONFLICT`, `EDIT_STALE_READ`, `EDIT_TARGET_MISSING` 등 기존 허용 코드이며 `result_unknown=False`인 미적용 오류만 기존 교정 한도에서 처리한다.

1. 실패한 단일 파일의 정확한 `source/...` 경로로 읽기를 요구한다.
2. 실제 읽기 성공 시 받은 SHA-256을 다음 쓰기·편집의 `expectedSha256`에 고정한다.
3. 선택한 파일과 해시를 모델에만 안내하는 데 그치지 않고 실제 호출 직전에도 검사한다.
4. 변경이 없는 수정은 기존 다른 파일의 변경 여부로 통과시키지 않는다.

부분 실행된 배치 전체를 자동 재전송하지 않는다. 결과 불명, 인증·권한 거부, timeout 등의 경로를 복구 대상으로 추가하지 않았다. 모델·Tool·교정·제품 수정 횟수 및 시간 한도는 그대로다.

## 새 SCN-001 실험 설정

공개 연결 계약은 회원가입 API·DB이며 HTML 회원가입 화면은 지정하지 않는다. `run_scn001_smoke.prepare()`는 새 실행 폴더에 도구 설정을 만들 때 `SCN001_API_DB_SECURITY_NO_UNSPECIFIED_UI_V1` 정책으로 데모용 생성 브라우저 scope를 제외한다.

- 원본 로컬 설정, 이미 승인·실행된 Run, 과거 실험 폴더는 변경하지 않는다.
- 브라우저 설정에 PROTECTED 등 생성 시험 외의 scope가 있으면 제외하지 않고 오류로 중단한다.
- UI가 명시된 계약에는 이 API 전용 설정을 적용하지 않는다.
- 단위·보안·개발 중 공통 보호시험과 독립 최종 시험은 유지한다.
- 네 조건에 동일한 대상 정책을 적용하고 비교 공통 설정에 기록한다. Ver1·Ver2의 보호시험 제공 차이는 그대로다.

일반 Host에서 이미 승인한 브라우저 시험을 무시하는 변경은 아니다. 브라우저 시험이 승인된 실행은 필수 파일·실제 ID 검사를 계속 수행한다. 새 조건은 91번과 다른 구현·실행 설정이므로 결과를 섞어 집계하지 않는다.

## 집계와 버전

비교 실행기는 실제 제품 실패, 평가 없음, 평가 미확정, 독립 전체 PASS, Host SUCCESS를 각각 집계한다. `meanPassingVerdictSeconds`에는 독립 전체 PASS이면서 Host도 SUCCESS인 실행만 포함한다. `UNVERIFIED`의 판정 시각은 성공 판정 시간에 넣지 않고, 전체 경과 시간은 별도로 유지한다. 시간·비용·수정 횟수 지표를 삭제하지 않는다.

공통 역할 지침과 Single 프롬프트 버전은 6이다. 새 검사·탐색·ID 목록·도구 인자 제한의 구현도 Host 정책 해시에 포함했다. A2A 메시지·Artifact 스키마·승인 요구사항은 변경하지 않았다. Single은 동일한 정체성·Context 안에서 같은 검사와 복구 규칙을 적용한다.

## 검증 상태

- 수정한 Python의 AST 문법 검사와 `git diff --check`만 수행했다. 프로젝트 모듈을 import하거나 테스트 코드를 실행한 검사가 아니다.
- 회귀 테스트를 추가했지만 **실행하지 않았다**. 대상은 혼합 단위·브라우저 탐색, 패키지·별도 scope, 누락 파일의 정확한 경로 교정, Source 위험 경로, Single·Multi의 CAS 복구, API 전용 설정, 결과 집계 분리다.
- 실제 API·Docker·서버 실행과 통과율·시간·비용 재측정은 하지 않았다. 이전 40회 결과 파일도 보존했다.
- 따라서 코드 변경 완료와 실행 검증 완료를 구분한다. 이 문서는 완제품 통과율 상승이나 완전한 오류 제거를 주장하지 않는다.

다음 **93번**: 사용자가 실행을 요청하면 회귀 검사부터 수행하고, 네 조건 소규모 실행으로 QA 보고서 → 제품 수정 → 재검증 → 최종 판정의 연결을 확인한다. 이를 확인한 후 동일 조건의 반복 측정을 진행한다.
