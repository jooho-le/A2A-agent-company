v1·v2는 Build 실패로 QA·Security 검증에 넘기지 않았다. 두 번의 수정은 동일 Run 안에서 기존 한도로 처리됐다. 별도의 유료 Run을 두 번 추가한 것이 아니다.

공급자 일시 오류 후 기존 정책에 따른 재시도 1회, 질문 재안내 1회, Source 교정과 Security 시험 쓰기 교정도 기록됐다. 재시도·출력 교정과 제품 코드 수정 2회는 별도 지표다. MCP 33개 시도는 모두 종료 기록이 있으며 결과 불명은 0개다.

## 공백 이메일 문제 확인

최종 v3 Source를 실행하지 않고 AST로 확인했다. `signup()`은 `normalize_email(request.email)`을 호출하고, 이어서 그 결과를 `validate_email(normalized_email)`에 전달한다. 정규화 함수는 먼저 공백을 제거하고, 로컬 부분·도메인에 승인된 소문자 규칙을 적용한다. dot/plus 제거는 추가하지 않았다.

실제 독립 평가에서도 공백·대소문자 변형의 정규화 저장 검사인 SEC-SIGNUP-003이 PASS다. Source의 설명만 보고 통과시킨 것이 아니며, 코드를 사람이 교체한 결과도 아니다.

## 반드시 구분할 한계

### 1. 자체 생성 시험과 보호시험의 결과가 다름

Agent 보고서의 QA 생성 시험 5개는 FAIL, 공통 QA 보호시험 6개는 PASS다. Security 보고서의 요구사항 결과 3개도 FAIL로 기록됐다. 이를 보고서에서 모두 PASS로 고쳐 쓰지 않았다.

Host는 실행 전에 동결된 **Ver1 보호시험 우선 판정 규칙**에 따라 같은 요구사항의 보호시험 통과를 반영했다. 이후 독립 최종 9개 실행 검사도 모두 통과했다. 따라서 이번 결론은 Ver1의 Host 성공과 최종 제품 통과이며, 자체 생성 시험의 품질까지 해결됐다는 뜻은 아니다. 보호시험이 없는 Ver2에서도 같은 결과가 나올지는 별도 검증이 필요하다.

### 2. 비용과 토큰의 전체 합계를 확정할 수 없음

15번 모델 호출은 `LLM_PROVIDER_ERROR`로 끝났고 사용량이 없다. 이후 기존 허용 범위에서 재시도해 Run은 계속됐다. 이 호출의 사용량·청구액을 0으로 추정하지 않는다.

33개 호출 중 32개의 비용 합계가 $0.1630532다. 전체 `costUsd`와 토큰 합계는 `null`, `costComplete`·`usageComplete`는 false로 보존했다. 확인된 32개의 토큰은 입력 463,633 / 출력 19,984다. 비용 비교에서 이 하한을 완전한 실행당 비용으로 평균내면 안 된다.

### 3. 서로 다른 시간 지표

245.496초는 Run 시작부터 Host SUCCESS까지 측정한 시간이다. 독립 평가의 **최초 통과 Snapshot 산출 시간(TIME-05)**은 앞선 후보의 평가가 확정되지 않아 `EARLIER_PASS_UNVERIFIED`로 남았다. 이를 최초 Build PASS 시간이나 성공 판정 시간으로 임의 대체하지 않는다.

### 4. 보조 검사와 전체 기록 보안

보조 정적 검사는 REQ-003을 `EMAIL_NORMALIZATION_MISSING`으로 FAIL 표시했다. 최종 Source의 전처리 함수와 실제 API 시험 PASS를 함께 보존하며, 이 정적 판정과 실행 판정의 차이는 추가 검토 대상으로 남긴다. 이번 작업에서 채점기를 변경하거나 결과를 삭제하지 않았다.

별도 Run 기록 비노출 검사는 관찰 범위가 부족해 UNVERIFIED, 추적 검사는 PASS다. 제품 시험 SEC-SIGNUP-005의 PASS만으로 모든 Agent 출력·전체 기록의 비노출까지 증명했다고 표시하지 않는다.

## 실행 조건·개발정의서 점검

- 자연어 요청, 모델·temperature, 시작 코드·이미지, 모델·Tool 각 200회, 실행 1,200초, 총 토큰 한도 2,000,000을 유지했다.
- 단계별 출력 교정 2회·공급자 재시도 1회·기존 제품 수정 한도를 늘리지 않았다. 정책·가격표·시험 기준을 실행 도중 바꾸지 않았다.
- 제출 기록은 정확히 1건이며, 자동 재제출·수동 Source 수정은 없다. 구현 파일의 실행 전후 SHA-256이 일치한다.
- Orchestrator 판정 책임, A2A·Artifact·불변 Snapshot·승인·인증·역할 권한·격리를 보존했다. 통과를 만들기 위한 계약 완화는 하지 않았다.
- `.env`·사용자 설정·이전 Run·100번 진단 복사본을 변경하지 않았다. 프로젝트 Git 커밋·푸시는 하지 않았다.
- 종료 후 실험 Host·Agent 포트 18002·18101~18104와 Docker 컨테이너가 남지 않음을 확인했다. 기존 Docker 데몬은 유지했다.
- 원본: `.data/experiments/scn001-multi-ver1-post100-20261123/`. Source v1~v3, 실행 영수증·Trace·전체 평가 결과를 보존했다.
