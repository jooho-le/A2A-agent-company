## 병합 기준

PR #28은 새 3D 오피스·병렬 작업 화면 변경을 되돌리는 PR이다. 두 PR을 함께 반영하는 최종본은 이 복원 의도를 따른다. 앞서 PR #29만 대상으로 준비했던 새 오피스 변경을 최종본에 다시 삽입하지 않는다. PR #28의 변경·삭제 대상 14개 파일이 복원 브랜치와 일치함을 확인했다. PR #28에서 되돌리지 않은 dev의 테마·배치 변경은 유지한다.

PR #29의 최신 Agent·MCP·Orchestrator·평가 구현과 제품 접수 오류 수정은 보존한다. 역할 계약, 시작 코드 초기화 보존, 정규화·비밀번호 비노출 안내, 생성 시험 fixture 오류 구분, 파일 수정 해시 검증, OpenAI 실패 분류·재시도 한도, Source 수정 한도 소진 판정을 유지한다. DB 업그레이드·미접수 키 정리·JWT·승인 Configuration·중복 생성 방지도 그대로 둔다.

## 충돌 해소

Agent 보완이 다른 커밋 이력으로 들어가 45개 파일에서 내용 또는 add/add 충돌이 발생했다. 두 브랜치의 직접 차이와 함수 정의·정책 버전을 대조했으며, 충돌 파일의 dev 버전에만 있는 함수·클래스 정의는 없었다. 최신 jooho 구현이 공통 보완과 후속 수정을 포함하고 있어 이를 유지했다.

자동 병합된 `src/mcp_tools/tools/files.py`에는 구버전 `_write_source`가 중복 삽입되어 최신 메서드를 덮어쓰는 문제가 있었다. 이 중복도 제거하여 새 파일 생성의 원자적 부재 검사와 기존 파일 교체의 해시 검증을 유지했다. 최종 `src/` 전체가 검토한 최신 jooho와 바이트 단위로 같음을 확인했다.

## 테스트 보완과 검증

전체 프론트 검사에서 예전 테스트가 현재 제품 전송 차단, 등록 SCN-001 UUID, 로그인 버튼, 간소화한 작업 이력, 등록 Source의 ZIP 다운로드와 맞지 않는 문제를 발견했다. 서비스의 인증·승인·기본 차단 규칙은 바꾸지 않고 테스트의 Mock 전송 경계·공개 응답·화면 기대만 수정했다. 무한 대기하던 Mock POST 대기도 제한했다.

| --- | --- |
| 최종 프론트 전체 검사 | 215개 통과, 실패·건너뜀 없음 |
| 제품 서버 접수·프로젝트·복구 검사 | 42개 통과 |

검사는 임시 병합본, 임시 DB와 Mock 통신에서 수행했다. 실제 OpenAI 호출·Docker 실험·서비스 서버 기동은 하지 않았다. 기존 환경 설정·DB·로그인 데이터·발표 자료를 변경하거나 초기화하지 않았다.

## 반영 순서

두 브랜치 이력을 보존하는 병합 커밋으로 jooho의 충돌을 해결한다. GitHub에서 PR #28을 dev에 병합하고, 이어 PR #29를 병합한다. 강제 푸시나 브랜치 삭제는 하지 않는다. 최종 dev에 두 PR의 head가 포함됐는지, 최종 트리가 검증한 결과와 같은지 확인한다.
