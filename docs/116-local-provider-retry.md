# 116. 로컬 서비스의 AI 제공자 오류 1회 재시도 적용

작성일: 2026-11-26.

## 확인한 원인

Run `072f1f0f-b8f0-4d5b-b420-61d409874f91`에서 Planner는 완료됐다. Developer는 프로젝트 파일을 두 번 정상 조회한 뒤 다음 OpenAI 요청에서 약 40.5초 후 HTTP 500을 받았다. QA 단계에는 도달하지 않았다. 기록의 분류는 `LLM_PROVIDER_ERROR / HTTP / SERVER_ERROR`다. OpenAI 내부의 구체적인 실패 원인까지 확인된 것은 아니다.

재시도 엔진은 이미 있었지만 로컬 실행 파일의 `llmLimits`에 `max_provider_retries`가 없어 기본값 0이 적용됐다. 따라서 첫 제공자 오류가 그대로 단계 실패가 됐다.

## 적용한 변경

`configs/owned-runtime.local.json`의 기존 설정을 비공개 `.data/backups/runtime-configuration/`에 백업한 뒤 다음 한 항목을 추가했다.

```json
{
  "llmLimits": {
    "max_provider_retries": 1
  }
}
```

위 JSON은 추가한 항목만 보여주는 예시다. 기존 model·토큰/시간/호출 예산·기타 llmLimits 항목은 보존했다. `.env`, 인증, 이미지, Source, QA 기준, 실험 Ver1·Ver2 설정을 변경하지 않았다. 기본 LLMLimits나 재시도 엔진 코드도 바꾸지 않았다.

기존 엔진의 제한을 그대로 사용한다.

- 일시적인 HTTP 500/503 등 재시도 대상 오류는 제한적으로 1회 재시도한다. 재시도도 원래 Run의 호출·시간·토큰 예산 안에서 수행한다.
- 이미 실행한 파일 수정·도구 작업 전체를 되풀이하지 않고 실패한 AI 요청의 복구 경로를 사용한다.
- 인증·요금/한도 문제, 결과가 불확실한 읽기 타임아웃을 무조건 반복하지 않는다.
- 재시도 후에도 제공자 오류가 지속되거나 예산이 부족하면 실패로 남긴다. 성공을 보장하는 변경은 아니다.

## 적용과 확인

실행 중인 Run이 없음을 확인한 후 Host와 에이전트 4개만 정상 종료하고 재시작했다. 제품 서버·프론트·기존 작업 기록은 유지했다. 기존 Run의 동결 정책이나 예산을 수정하지 않았으며 대기/실패 작업을 자동 재개하지 않았다.

| 확인 | 결과 |
| --- | --- |
| 실제 REST 어댑터·엔진의 격리된 오류/재시도 검사 | 61개 통과. MockTransport를 사용하며 실제 OpenAI 호출 없음 |
| 승인 Host 설정과 키 존재 검사 | 통과. 키 값은 출력하지 않음 |
| 재시작 후 Host·Agent 4개·제품·프론트 | HTTP 200 |
| 서비스 승인 Configuration 조회 | HTTP 200 |
| 새 AI 작업 자동 실행 | 수행하지 않음 |

## 사용자가 할 일

1. `http://localhost:5173`에서 `⌘ + Shift + R`로 새로고침한다.
2. **새 작업 만들기**를 선택한다.
3. `이메일과 비밀번호로 회원가입 API 만들어줘.`를 입력하고 시작한다.

변경된 실행 규칙은 새 작업부터 적용된다. 기존 실패 작업의 답변 이어가기를 누르지 않는다. 실제 API에서 재시도 후 완료되는지는 이 새 작업의 기록으로 확인해야 한다.

로컬 runtime JSON과 백업은 Git 제외 대상이다. 이 문서만으로 다른 팀원 PC의 설정이 자동으로 바뀌지는 않는다.
