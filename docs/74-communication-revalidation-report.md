[보강 후 실제 통신 재검증 PDF](reports/agent-communication-revalidation-2026-11-13/revalidation-report.pdf)는 총 6쪽이다. 결론 → 자연어 원문 3개·실행 방법 → 15건 송수신 → 의미 검토 → 속도 → 이전 자료와 비교·한계 순서로 읽을 수 있다.

기존 정리된 회원가입 보고서와 11월 10일 자연어 보고서는 그대로 보존했다. `docs/reports/`에는 이번에도 **PDF만** 추가했다. 출력용 HTML과 브라우저 검증 자료는 `/private/tmp/`에 두었다.

## 1. 전부 보내고 제대로 받았나

이번 실제 API 요청 15건은 원문에서 실행기까지, DB 접수 기록, API 실제 입력, 응답·metadata가 모두 일치했다. HTTP 200만 확인한 결과가 아니다. 모델 서버 Request ID도 15개 수집했다.

이는 **이번에 관측한 15건의 통신 보존**을 뜻한다. 높은 동시 접속·서버 재시작·장시간 실행에서 유실이 항상 없다는 보장은 아니다. DB 기록의 대조와 API 입력 대조도 각각 별도 관측값으로 남겼다.

## 2. 할루시네이션은 없었나

**없다고 단정할 수 없다.** 닫힌 역할 Schema 위반·없는 원문 인용·미실행 성공 선언 등 자동 불변조건 위반은 0건이었다. 그러나 원문과 응답을 사후 대조했을 때 의미를 넓혀 해석하는 위험은 남았다.

| 요청 | 실제 응답에서 본 내용 | 판단 |
| --- | --- | --- |
| 블로그 | 댓글은 가정·추가 질문에 남겼지만, Planner의 검사 기대값은 “여러 명이 동시에 게시글 작성 및 댓글 작성이 가능하다.”라고 작성 | 승인 전 제안이 필수 검사로 쓰일 위험. 보안 본문의 동아리 전용 접근 제한도 사용자 확인 필요 |

Codex가 실제 응답 15개의 요구사항·가정·질문·검사·역할 본문을 검토했다. 이는 독립 사람 채점이나 별도 유료 평가 모델의 판정이 아니다. 예시 2개를 곧바로 할루시네이션 발생률로 계산하지 않는다.

보고서에 실은 원문과 응답 인용은 `validate_review()`가 **같은 케이스·구조·역할의 실제 자료에 존재하는지** 다시 확인한다. 인용의 존재를 검증하는 기능이며, 해석의 정확성을 자동 판정하는 기능은 아니다.

이번 자연어 진단은 제품 승인 원장과 동일한 경로가 아니다. 따라서 이 결과는 승인 정책 구현 자체의 통과·실패 증거가 아니며, 진단의 의미 검사와 실제 Host 연결을 나누어 확인해야 한다.

## 3. 속도는 얼마나 달랐나

역할별 표본은 각 3개다. 완료 행만 사용하고, 없는 구간·음수·비정상 수치·실패 표본을 0초나 빠른 성공으로 넣지 않는다.

| 역할 | Agent 처리 중앙값 | API 교환 중앙값 | 로컬 전달 중앙값 |
| --- | ---: | ---: | ---: |
| Planner | 8.408초 | 8.386초 | 0.806ms |
| Developer | 9.168초 | 9.100초 | 1.047ms |
| QA | 10.766초 | 10.519초 | 2.661ms |
| Security | 10.498초 | 10.477초 | 24.810ms |
| Single | 10.456초 | 10.420초 | 1.014ms |

짧은 로컬 전달과 긴 원격 API 교환은 서로 다른 구간이다. 속도 차이 자체는 데이터 유실의 증거가 아니며, 전달 여부는 위 송수신 대조로 판단한다. API 교환에는 네트워크·서버 처리·본문 수신이 포함되어 순수 모델 추론 시간은 알 수 없다.

Security의 로컬 전달 중앙값은 다른 역할보다 컸다. 다만 같은 프로세스의 이벤트 루프·병렬 요청 스케줄링도 포함하는 소수 표본이므로, Security 자체의 처리 문제나 데이터 누수로 원인을 단정하지 않는다.

| 케이스 | Multi 진단 실행 | Single 진단 실행 |
| --- | ---: | ---: |
| 블로그 | 22.779초 | 5.875초 |
| 전자문서 | 29.010초 | 10.569초 |
| 추리게임 | 49.509초 | 11.817초 |

Multi는 역할 4회, Single은 1회이며 출력량도 다르다. 이 시간은 제품 개발 완료시간이나 구조 자체의 성능 우열이 아니다. QA·Security가 병렬인 구간을 단순 합산하지 않았다.

## 보고서 재생성

`src/diagnostics/communication/reporting.py`는 저장된 근거만 읽는 오프라인 집계·출력 모듈이다. API를 호출하거나 원자료를 수정하지 않는다. 미관측은 일치로 집계하지 않고, `SKIPPED`와 전송 불일치를 구분한다. 기록 없는 비교 조건은 `None`으로 남긴다.

```bash
PYTHONPATH=src .venv/bin/python -m diagnostics.communication.reporting \
  --evidence .data/diagnostics/natural-language-3cases-2026-11-13-hardened/run.json \
  --review .data/diagnostics/natural-language-3cases-2026-11-13-hardened/review.json \
  --baseline .data/diagnostics/natural-language-3cases-2026-11-10-redo-01/run.json \
  --out /private/tmp/a2a-73-74-report.html
```

이 HTML을 임시 프로필의 Chrome으로 A4 PDF 출력했다. PDF 재출력은 API 재실행이 아니다. 원자료가 없는 다른 환경에서는 기존 PDF로 결과를 확인하고, 새 실행 근거 없이 같은 수치를 재현했다고 선언하지 않는다.
