# 121. 보안 검사 인자 오류와 잘못된 제품 수정 경로 보완

작성일: 2026-11-27.

## 이번 실패의 실제 원인

Run `333030fc-d2ba-48d9-bec7-f437cd2542b7`은 Source v2에서 QA **8/8 통과**, Build PASS까지 도달했다. Security의 마지막 검사는 제품에 요청하기 전에 준비 코드에서 실패했다.

실제 생성된 검사 13번째 줄의 호출 형태는 다음과 같았다.

```python
self.check_http_output(
    client=self.client, method="POST", path="/signup",
    sensitive=sample, json=payload,
)
```

120번의 공통 메서드는 자체적으로 `self.client`를 전달하면서 `**request`에 남아 있던 `client`도 전달했다. 같은 인자가 두 번 들어가 `TypeError`가 발생했다. 실행 전 검사는 이 호출을 허용했지만 실제 공통 메서드는 처리하지 못했다. **120번 수정에서 이 계약 차이와 오류 분류를 놓쳤다.**

이 TypeError가 일반 FAIL로 보고되면서 제품 수정 요청이 만들어졌다. Developer는 바꿀 제품 코드가 없어 동일한 코드를 제출했고, 무변경 종료 규칙인 `LLM_DEVELOPMENT_NO_PROGRESS`로 끝났다. 화면 안내 사전에 이 코드가 빠져 있어 마지막 원인도 일반적인 “직원 실행 실패”로 표시됐다.

## 변경

1. 공통 메서드가 선택적 `client` 키워드를 명시적으로 받는다. 생략하면 현재 검사의 `self.client`를 사용하고, 지정하면 **같은 객체일 때만** 허용한다. 임의 클라이언트로 원래 앱의 시작 절차를 우회할 수 없다. 공개 메서드 설명과 실제 함수 시그니처를 함께 검증한다.
2. 공통 출력 관찰 도구는 HTTP 요청을 호출하기 전에 인자 바인딩을 확인한다. 잘못된 키워드, 빠진 필수 인자, 잘못된 클라이언트와 합성 데이터는 확인된 검사 도구 오용으로 분류한다.
3. `TypeError`라는 문구만으로 결과를 바꾸지 않는다. 실제 Host 도구 함수의 프레임·호출 위치·함수 객체·시그니처 바인딩으로 증명된 경우에만 `NOT_RUN_FIXTURE_ARGUMENT_INVALID`를 기록한다. 앱이나 요청 구현 내부에서 난 TypeError, 일반 검사 코드 오류, 정보 노출 검사는 실제 실패로 유지한다.
4. 기술적 미실행은 기존 한도 내에서 **같은 Security 단계의 검사 파일 수정**으로 돌린다. 수정 기회가 끝나도 `SECURITY_TESTS_NOT_RUN / UNVERIFIED`를 유지하며 제품 결함이나 PASS로 바꾸지 않는다. 실제 Security 결과 조립 함수까지 이 경로를 검증했다. 요구사항·Source·검사 항목·수정 한도는 변경하지 않았다.
5. `LLM_DEVELOPMENT_NO_PROGRESS`를 비롯해 응답 형식·소스 근거 오류에 구체적인 화면 안내를 추가했다. 기존 종료 기록은 덮어쓰지 않는다.

## 원본 그대로 재현한 결과

유료 모델을 새로 호출하지 않고, 보존된 **Source v2 스냅샷과 실제 QA·Security 검사 파일**을 사용했다. 저장된 해시와 원본 바이트를 확인했고, 소스·검사 내용은 수정하지 않았다. 실행은 기존 승인 이미지의 비특권 Docker 안에서만 수행했다. 네트워크 차단·읽기 전용 마운트·자원 제한을 유지했으며 API 키를 전달하지 않았다.

| 확인 항목 | 기존 검사기 | 수정 검사기 |
| --- | --- | --- |
| 실제 앱 시작·인터페이스 빌드 검사 | 당시 PASS | PASS |
| 원본 QA 검사 | 당시 8/8 PASS | 8/8 PASS |
| 원본 Security 검사 | 재현 시 0/1, 같은 줄에서 TypeError | 1/1 PASS |
| 응답·요청 로그의 합성 비밀값 관찰 | 검사 전에 중단 | 두 채널 모두 CHECKED |

여기의 8+1은 이 서비스 작업에서 생성된 검사 수다. 성능 실험의 독립 최종 시험 수를 의미하지 않는다. 새 LLM 실행의 전체 자율 완료 여부는 이번 재생과 별도로 확인해야 한다.

개인 실행 근거는 Git 제외 경로 `.data/diagnostics/service-helper-replay-20261127.json`에 보관했다. 원본 스냅샷·수정 검사기 해시, 전후 결과, 유료 호출 0회를 기록했다. 기존 Run·Artifact·검사 이력은 변경하지 않았다.

## 회귀 확인

- 관련 회귀 검사 **264개 통과**. 서비스 검사기, 기존 SCN-001 준비 기능, QA/Security 결과와 수정 경로, 공개 오류 안내를 확인했다.
- 잘못된 클라이언트·누락 인자·지원하지 않는 HTTP 옵션은 미실행으로 분류되고, 요청 구현 내부나 다른 검사 코드의 TypeError는 실패로 유지되는 것을 확인했다.
- 기존 의도적 비동기 시험의 경고와 테스트 A2A event stream 경고 3건은 남아 있으며 실패 항목은 없다.

- 실제 유료 LLM 작업은 추가로 실행하지 않았다. 실패했던 Run의 종료 상태를 성공으로 바꾸지 않는다.
