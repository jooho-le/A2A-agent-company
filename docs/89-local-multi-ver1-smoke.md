# 89. Multi Ver1 로컬 실제 API 실행 및 QA 사전 검사 보완

## 작업 범위

2026-11-22에 실제 OpenAI API로 **Multi Ver1 한 번**을 실행했다. 사용자 요청은 `이메일과 비밀번호로 회원가입 기능을 만들어줘.`이다. 네 조건을 각각 10회 실행한 비교 실험이 아니라, 수정·검증 흐름을 확인하는 진단 실행이다.

현재 브랜치와 프로젝트 커밋은 변경하지 않았다. 로컬의 이전 코드에 이미 `origin/dev`의 `9d9094d`까지 병합된 Agent/MCP·Orchestrator·평가·스키마·관련 테스트 보완을 작업 파일로 반영했다. 이 동기화에 포함된 파일은 283개이며 프론트 파일, `.env`, 기존 로컬 설정과 과거 실행 기록은 수정하지 않았다.

작업 후 Git 상태에서 이름 끝이 ` 2.py`인 별도 중복 파일 85개도 관찰됐다. 이번 수정 산출물과 구분하며, 출처·보존 필요성을 확인하지 않고 삭제하거나 커밋하지 않았다. 이 문서의 회귀 검사는 파일 이름을 명시해서 실행했으며 중복 파일을 검사 수에 포함하지 않았다.

## 실행 설정과 재실행 방법

실행기: [`scripts/run_scn001_smoke.py`](../scripts/run_scn001_smoke.py)

실제 실행 전에는 Docker Desktop이 켜져 있어야 한다. 아래 실행기는 루트 `.env`를 읽으며 키를 쉘 명령에 직접 붙이지 않는다.

```bash
# 설정만 준비: 모델 호출과 Run 제출 없음
.venv/bin/python scripts/run_scn001_smoke.py

# 새 폴더에서 실제 API로 한 번 실행
.venv/bin/python scripts/run_scn001_smoke.py --run
```

| 항목 | 이번 실행 |
| --- | --- |
| 모델 | `gpt-4.1-mini-2025-04-14`, temperature 0 |
| 구조·정책 | Multi / 개발 중 공통 보호시험 제공 |
| 한도 | 모델·도구 각각 200회, 응답 출력 8,192토큰, 총 2,000,000토큰, 실행 20분 |
| 수정·복구 | 코드 수정 최대 3회, 출력 교정 2회, 질문 안내 1회, 제공자 재시도 1회 |
| 격리 환경 | 기존 로컬 Docker 이미지·시작 코드·의존성 lock 사용 |
| Host·Agent | `18002`, `18101`~`18104`; 기존 제품 서버와 분리 |
| 비밀값 | 루트 `.env`를 프로세스 환경에만 전달. `OPENAI_API_KEY`를 플랫폼이 사용하는 키 이름으로 연결 |
| 보호시험 | 현재 소스의 순환용 시험과 케이스를 새 설정에 고정. 최종 시험은 개발 입력에 제공하지 않음 |

기존 설정을 덮어쓰지 않고 실행마다 새 DB·작업 폴더를 만든다. Run 생성 POST는 한 번만 보내고 중복 방지 키를 기록한다. 제출 응답이 불명확해도 자동 재제출하지 않는다. 기존 실행 폴더를 다시 지정하면 덮어쓰지 않고 중단한다. 실행 후 이 실행기가 시작한 Host·Agent는 종료한다.

### 제품에서 실제로 확인한 실패

QA 검사 6개와 비밀번호 저장·DB UNIQUE 보안 검사는 모두 통과했다. `SEC-SIGNUP-005`에서만 실패했다. 필드 누락·목록 형태 본문·필드 이름 오타 요청의 기본 검증 오류 응답에 입력 비밀번호가 포함됐다. 생성된 앱에는 `RequestValidationError` 응답에서 입력값을 제거하는 별도 처리기가 없었다.

이는 **회원가입 대부분이 동작해도, 비노출 요구사항 하나 때문에 완제품은 탈락할 수 있음**을 보여준다. 과거 석민 담당자의 40회 실험 전체가 같은 이유였다는 증거는 아니다.

### 실행 흐름에서 실제로 확인한 실패

기획·개발 단계는 성공했고, Security 보고서도 만들어졌다. QA는 `QA_TEST_INPUT_INVALID`로 실패했다. 필수 `qa-browser`의 `outputs/qa/tests/browser/suite.json`이 없었는데도, 완료 응답을 받기 전 검사는 단위 테스트 파일만 검사했다. 이후 Host가 모든 승인된 시험 범위를 실행하려다 브라우저 입력을 준비하지 못하고 중단했다. 최종 판정과 코드 수정 요청까지 이어지지 못했다.

## 추가 수정

1. **필수 브라우저 입력을 READY 전에 검사한다.** 파일 누락, 선언형 JSON 형식, 허용 동작, 실제·선언 테스트 ID 일치를 확인한다. 심볼릭 링크와 범위 밖 경로는 허용하지 않는다. 시험 파일을 Host에서 실행하거나 보호시험을 생략하지 않는다.
2. **기존 한도 안에서 수정 안내를 보낸다.** 누락은 기존 `GENERATED_TESTS_INVALID` → 파일 작성 교정 경로를 사용한다. 수정 횟수·권한·승인 기준은 완화하지 않았다.
3. **공유 역할 지침을 보완한다.** 비밀번호 비노출은 정상 응답뿐 아니라 요청 검증 오류와 DB 예외·로그에도 적용된다는 점을 Single·Multi 공통 지침에 명시했다. 숨겨진 시험 입력이나 정답 코드는 제공하지 않았다.

이 추가 수정은 **위 실제 실행이 끝난 다음** 적용했다. 추가 유료 Run은 제출하지 않았고, 수정 후 검증은 오프라인 회귀 검사로만 했다. 따라서 이번 결과를 수정 후 성공 결과로 표시하지 않는다.

## 검증 및 원본 위치

- 변경 전에는 단위 파일만 있고 필수 브라우저 파일이 없는 READY가 사전 검사를 통과하는 회귀 사례를 재현했다.
- 변경 후 같은 사례가 파일 작성 교정으로 연결되고, 올바른 브라우저 파일과 테스트 선언이 있어야 통과함을 확인했다.
- 누락·잘못된 JSON·허용하지 않은 동작·ID 불일치·심볼릭 링크, 키 전달과 기존 설정 보존을 검사했다.
- 기존 보호시험 충돌 판정·수정 피드백·수정 정체 관련 unittest 37개 통과.
- 첫 pytest 관련 검사 56개 통과. 브라우저 교정 경로 추가 후 해당 파일 8개 통과. QA 실행기·검증 서비스·Single Ver1·Single 프롬프트·입력 저장 관련 회귀 검사 85개 통과. 검사 묶음 사이 일부 재검사가 있으므로 이 수치를 단순 합산하지 않는다.

## 개발정의서 점검과 다음 작업

동결 요구사항·시작 코드·동일 Snapshot 검증, 보호시험 보존, 실제 도구 증거 기반 판정, 인증·Docker 격리를 유지했다. 프로젝트 커밋·푸시와 기존 실행 재개는 하지 않았다. 이번 한 건만으로 Single/Multi 성능 우열이나 10회 성공률을 주장하지 않는다.

당초 다음 90번은 실제 API 재확인이었으나, 사용자 요청에 따라 [90번 전체 에이전트 보강](90-agent-quality-hardening.md)을 먼저 진행했다. 실제 API 재확인은 91번으로 이어가며, QA 보고서 생성 → 필요한 코드 수정 → 재검증 → 최종 판정까지 확인한 뒤 네 조건의 반복 비교를 진행한다.
