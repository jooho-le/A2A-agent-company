# 쉬운 사용 흐름으로 정리

## 기본 흐름

1. **만들기**: 프로젝트 이름과 요청을 입력한다. 비로그인 사용자는 `로그인하고 시작`으로 이동하며 입력은 유지된다.
2. **진행 상황**: 지금 하는 일과 직원 상태를 먼저 보여준다. 작업 기록은 펼쳐서 확인한다.
3. **결과물**: 프로젝트를 선택해 결과 정보를 확인한다. 결과가 없거나 조회에 실패한 경우를 구분한다.

작업 중에는 [직원 작업 패널](owner-work-controls.md)에서 직원을 눌러 작업 내용을 확인하고, 질문에 답하거나 상단의 `작업 중단`으로 현재 실행을 종료할 수 있다. 진행 중인 추가 의견은 메모로 보관하고 확인 대기 때 답변으로 전달한다.

## 줄인 정보와 동작

- 긴 제목·영문 장식·반복 설명을 줄였다. 직원 소개는 보조 메뉴로 옮겼다.
- 오피스는 휴대폰에서도 요청창을 먼저 보여준다. 작업을 선택하면 요청창을 접고 진행 상황을 연다. 카메라 설정과 상세 기록은 접어둔다.
- 직원은 `팀장·기획·개발·품질 검사·보안 검사`로 표시한다. 실제 Agent 역할·프로토콜 값은 유지한다.
- 프로젝트·실행·설정 식별자는 상세 정보에서 볼 수 있다. 목록에는 이름과 날짜를 먼저 보여준다.
- 빈 프로젝트·진행·결과 화면에 다음 행동 버튼을 넣었다. 프로젝트 상세에서는 저장된 작업의 `진행 보기`로 연결한다.
- 로그인·회원가입은 중앙 팝업형 배치를 유지하고 설명을 줄였다. 닫기 버튼을 추가했다.

## 유지한 계약과 한계

- 로그인, 승인 Configuration, 중복 접수 방지, 미확정 접수 복구, 서버 검증·상태 판정은 그대로다. 종료·실패·미검증을 성공으로 표시하지 않는다.
- 현재 안내된 지원 범위는 회원가입 기능이다. 화면 문구를 줄이면서 이 범위는 숨기지 않았다.
- 문서 수신자는 기존 API에서 회원번호를 요구한다. 검색 API를 가정하지 않고 입력 항목을 유지했다.
- 결과물의 원문 조회·다운로드는 기존 API가 제공하지 않아 추가하지 않았다. 화면에서 지원 여부를 짧게 안내한다.

## 검증

- 기존 UI 테스트를 새 메뉴·버튼·문구에 맞추면서 인증 차단·입력 보존·승인 차단·중복 방지·복구·비밀값 미노출 검증을 유지했다.
- 최종 판정이 성공이 아닌 종료 상태와 알 수 없는 상태를 완료로 안내하지 않는 테스트를 추가했다.
- 임시 Chrome에서 입력 → 로그인 → 입력 복원 → 저장된 작업 선택 → 진행·결과 이동을 점검했다. 로그인과 조회 응답은 격리 데이터이며 실제 계정·작업 생성은 하지 않았다.
- 390px·320px에서 주요 메뉴의 가로 넘침과 런타임 예외가 없었다. 실제 서비스 서버는 계속 실행 상태로 유지한다.
- 프론트 테스트 197개, 빌드, ESLint를 통과했다. 생성 코드의 실제 빌드·검증이나 유료 모델 실행을 이번 화면 점검의 결과로 주장하지 않는다.
