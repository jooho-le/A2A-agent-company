# 105. 시험 계약 보완 후 4조건 실제 API 단회 비교

작성일: 2026-11-23. 요청 **“이메일과 비밀번호로 회원가입 기능을 만들어줘.”**를 같은 구현에서 Single·Multi × Ver1·Ver2에 각각 한 번씩 제출했다. **새 Run은 정확히 4건**이며, 실패 후 재제출·수동 Source 수정·실행 중 코드 변경은 없다.

## 각 조건에서 일어난 일

### Single Ver1 — 제품 통과와 자동 완료

초기 v1이 Build와 독립 최종 9개 검사를 통과했고, Host도 SUCCESS로 종료됐다. 같은 Single Agent 서버가 업무 단계를 수행했다.

다만 자체 생성 시험이 모두 정상이라는 의미는 아니다. 생성 QA는 3 PASS·2 FAIL, Security는 첫 실행 2 PASS·1 FAIL, 재실행 1 PASS·2 FAIL로 기록됐다. 실행 전에 고정된 **Ver1의 공통 보호시험 우선 규칙**과 독립 최종 제품 통과를 구분해서 해석한다. 생성 시험 실패 기록을 지우거나 PASS로 고쳐 쓰지 않았다.

### Multi Ver1 — 제품은 통과, Security 시험 파일에서 중단

v1 제품은 공통 보호시험과 독립 최종 9개 검사를 모두 통과했다. 그러나 Security 작업의 최종 상태는 `SECURITY_TEST_INPUT_INVALID`였고 Host는 HUMAN_REVIEW로 멈췄다.

최종 Security 시험 파일에는 실제 NUL 바이트가 들어 있어 유효한 Python 파일이 아니었다. 별개로 QA 생성 시험 5개는 출력 검사 함수의 `SUPPLY_SYNTHETIC_PASSWORD_PRESENT_IN_REQUEST`에서 실패했다. 실행 입력 해시와 현재 QA 파일 해시가 일치함을 확인했고, 시험은 문자열 인자 자리에 **비밀번호 변수를 감싼 목록**을 전달하고 있었다. 따라서 이 5건을 제품 API 결함으로 집계하지 않는다.

### Single Ver2 — 실제 로그 해시 노출과 시험 입력 오류가 함께 존재

첫 Build 실패 후 같은 Run 안에서 수정해 v2가 등록됐다. 독립 최종 시험은 **8 PASS·1 FAIL**이다.

실패 검사는 **SEC-SIGNUP-005 비밀번호·해시 노출**이다. 세부 기록에서 `application_logs / hash_exposed`, `application_logs / hash_in_crash`가 FAIL이다. 즉, **앱의 오류 로그·오류 기록에서 저장된 비밀번호 해시가 드러나는 제품 결함**을 실제 실행으로 확인했다. 평문 비밀번호가 모든 응답에서 유출됐다고 확대 해석하지 않는다.

또한 Security 작업은 `SECURITY_TEST_INPUT_INVALID`로 끝났고 최종 시험 파일에서도 NUL 바이트를 확인했다. 이 시험 작성 오류와 실제 제품의 로그 비노출 결함은 서로 다른 문제다. 공급자 오류 1건의 미확인 사용량도 비용 완전성에 따로 반영했다.

### Multi Ver2 — 편집 도구 거절 후 등록 후보 없음

Developer의 `edit_source_file`이 **`EDIT_TARGET_MISSING`으로 3회 거절**됐다. 실제 파일에서 찾을 수 없는 교체 대상을 지정한 경우이며, 최종 Task는 `LLM_TOOL_EXECUTION_FAILED`다.

빌드·QA·Security까지 넘길 등록 Source가 없어서 Host가 보류했고 독립 평가도 수행하지 못했다. 생성 중인 작업 폴더를 사람이 수정하거나 임의 후보로 채점하지 않았다. 도구 기록의 `resultUnknown=false`이므로 전송 결과를 모르는 데이터 유실과도 구분된다.

## 결론과 다음 작업

제품 9개 검사를 통과할 수 없던 상태는 일부 해소됐다. 그러나 **자동 실행의 안정성과 자체 생성 시험 품질은 아직 부족하다.** 이번 결과에서 실제로 확인한 보완 대상은 다음과 같다.

1. 시험 파일의 NUL 등 문법 오류와 helper 인자형 오류를 쓰기·READY 이전에 정확히 묶어 교정하고, 시험 작성 오류를 제품 수정으로 보내지 않기.
2. `EDIT_TARGET_MISSING` 이후에는 실제 파일·교체 문자열을 다시 대조해 수정하도록 복구 경로 보완. 파일 보호나 편집 검증을 끄지 않기.
3. SQL·오류 로그에서 저장 해시가 노출되는 경로를 Developer가 구현·재검증하도록 보완.

**다음 106번:** 위 실행 중단·시험 작성·로그 비노출 문제를 기존 근거로 보완한다. 추가 API 실험은 별도로 진행하며 이번 표를 만들기 위해 성공할 때까지 재실행하지 않았다.
