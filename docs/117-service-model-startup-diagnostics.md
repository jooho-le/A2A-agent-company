# 117. 서비스 모델 기본키 누락과 잘못된 수정 안내 보완

작성일: 2026-11-26.

## 실제 실패

Run `f7149f81-0fbc-47df-ae29-598d803b5ce3`은 `FINISHED / FAIL`, Source v3, 수정 2회로 종료됐다. Planner와 Developer 호출은 완료됐지만 생성된 제품의 Build는 세 번 모두 종료 코드 1이었다. QA·Security 단계에는 도달하지 않았다.

사용자 요청은 `이메일과 비밀번호로 회원가입 API 만들어줘.`였다.

| Source | 실제 변경 | 빌드 결과 |
| --- | --- | --- |
| v1 | User 모델과 가입 API, HTML 화면 생성 | `models.py:7`에서 앱 시작 실패 |
| v2 | models.py에 engine import 추가 | 같은 위치에서 실패 |
| v3 | models.py에 create_tables() 추가 | 같은 위치에서 실패 |

세 버전 모두 User의 email·password_hash 컬럼만 있고 **primary key가 없었다**. SQLAlchemy ORM은 모델을 읽을 때 기본키를 구성해야 하므로, 이 경우 테이블 생성/lifespan에 도달하기 전에 모델 매핑부터 실패한다. import나 테이블 생성 함수를 추가해도 해결되지 않는다.

기존 서비스 기동 검사가 이 원인을 `SERVICE_START_FAILED`로만 전달한 것이 잘못된 수정을 유발한 보완점이다. 실제 실패 기록의 기본키 누락은 Source와 설치된 SQLAlchemy의 매핑 검사 코드를 읽어 확인했다. 저장된 예외 원문을 확보했다는 의미는 아니다.

## 수정

1. Sandbox 기동 오류를 닫힌 코드로 구분한다. 기본키 누락은 `SERVICE_MODEL_PRIMARY_KEY_REQUIRED`, 기타 SQLAlchemy 정의 오류는 `SERVICE_MODEL_DEFINITION_INVALID`로 보고한다. import·이름·인자 오류도 각각 구분한다. 원문 예외 메시지·값은 출력하지 않는다.
2. 서비스의 명백한 기본키 누락을 READY 전에 정적으로 잡는다. 시작 코드의 평범한 SQLAlchemy Base와 엔트리포인트가 직접 import하는 명시적인 모델만 판정한다. 모델 이름을 User로 고정하지 않는다. 동적 매핑·상속·추상 모델·사용하지 않는 예제·조건부 import 등 불확실한 경우는 실제 Sandbox에 맡긴다.
3. 수정 안내에서 기본키 컬럼을 고치라고 알려준다. 단순 engine import나 create_tables() 추가로는 매퍼 정의 오류를 고칠 수 없음을 명시한다. 에이전트가 실제 Source를 수정하고 재검사하도록 하며, Host가 제품 코드를 임의로 바꿔주지는 않는다.
4. 서비스 의존성 오류에도 무조건 웹 화면을 만들라고 하던 공통 수정 안내를 바로잡았다. 원인 코드별로 승인 패키지·모델 기본키·요청된 WEB 화면을 구분해 안내한다.
5. 이번과 같이 화면 요청이 없는 명시적 한국어 `API 만들어줘` 요청은 Planner 출력 계약에서 API delivery와 JSON/EMPTY 응답만 허용한다. API를 언급했다는 이유만으로 모든 요청을 API로 분류하지 않는다. 화면+API 요청이나 모호한 표현은 기존 기획 판단을 유지한다. 잘못된 WEB 계획을 조용히 덮어쓰지 않고 출력 검증에서 거절한다.

## 유지한 경계

- 기존 실패 Run·Source·BuildReport·Issue와 동결 요구사항을 변경하지 않았다.
- 실험 SCN-001 기준·공통 보호시험·MCP 권한·인증·수정 한도를 바꾸지 않았다.
- Single·Multi는 같은 사전 검사와 기획 계약을 사용한다.
- 검사에서 통과했다고 실제 기능 성공으로 취급하지 않는다. 최종 기능과 보안은 실제 실행 근거가 필요하다.
- 재시도 1회 로컬 설정은 유지한다. 생성 코드를 Host에서 실행하거나 새 OpenAI 요청을 보내지 않았다.

## 검증

- 서비스·기획·실행 입력·기본 기동·복합 수정 회귀 묶음: **120개 통과**.
- 마지막 기동 원인·명시적 API·기획 계약 묶음: **67개 통과**. 위 묶음과 중복되며 단순 합산하지 않는다.
- 구조 복구·완료 검사·수정 경로 묶음에서는 95개 통과, 기존 연속편집 검사 1개가 첫 전체 쓰기의 필수 expectedSha256을 누락해 실패했다. 파일 쓰기 정책은 유지하고 해당 검사 입력에 기존 파일 해시를 보완했다. 수정 경로와 신규 기동 검사 재확인은 **29개 통과**했다.
- 실제 저장된 Source v1·v2·v3를 임시 폴더에 읽어 수행한 비실행 정적 확인: 세 버전 모두 `models.py:7 / MODEL_PRIMARY_KEY_MISSING` 탐지.
- 변경 Python 8개 파일 구문과 diff 공백 검사 통과. 실제 API 기반 새 Run 성공은 아직 확인하지 않았다.
