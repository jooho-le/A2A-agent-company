# 프론트 상태 복원·화면 이동 오류 4건 수정

기준일: 2026-11-19. `dev`의 PR #22 반영 상태에서 추가로 재현한 오류를 수정했다.

## 변경 사항

| 문제 | 수정 후 동작 |
| --- | --- |
| A 계정 초안이 다른 계정 로그인 후에도 표시됨 | 이전·새 계정의 화면용 식별자를 비교한다. 다른 계정 또는 식별 불가 재로그인은 초안을 비우며, 동일 계정·로그인 취소·비로그인 작성 후 최초 로그인은 초안을 유지한다. |
| 두 번째 Run 선택 후 새로고침하면 첫 Run으로 바뀜 | 계정·프로젝트·Host·Run 식별자를 복원 후보로 저장하고, 로그인된 제품 API의 최신 프로젝트 이력과 대조해 정확한 Run을 선택한다. 저장된 Run이 사라졌을 때 다른 Run으로 임의 대체하지 않는다. |
| 실제 과거 기록이 있는데 작업 기록이 0건으로 표시됨 | `historyEntries`로 저장된 기록을 표시한다. 애니메이션용 `entries`에는 새로 관측한 이벤트만 전달해 과거 문서 이동을 재연하지 않는다. |
| 로그인·전자문서 화면에서 브라우저 뒤로가기가 화면을 닫지 않음 | 로그인·회원가입·전자문서·파이프라인 화면을 History 항목에 연결한다. 뒤로가기·앞으로가기·닫기가 같은 화면 상태를 복원하며, 취소 시 기존 대시보드와 Run을 유지한다. |

## 구현 경계

- `App.jsx`: 계정 변경 시 초안 정리와 계정 화면 전환을 처리한다. 새 로그인 성공 때 대시보드를 새 세션으로 분리하는 기존 동작은 유지한다.
- `useAccountNavigation.js`: History에는 화면 이름만 저장한다. 토큰·비밀번호·입력 초안·서버 응답을 넣지 않는다. 닫기 중복 클릭으로 여러 페이지를 건너뛰지 않도록 이동 중 재호출을 막는다.
- `projectSelection.js`: 선택 ID는 권한 증명이 아닌 후보다. 복원할 때 제품 서버의 JWT·소유권 검사와 프로젝트-Run 소속 확인을 거친다. 신규 생성 영수증이 확인된 시점에 후보를 저장하므로 이름 조회 이전에 새로고침해도 이전 Run으로 돌아가지 않는다.
- `agentRunEventFeed.js`: 과거 기록도 100개 단위로 처음부터 조회한다. 전체 묶음을 정상 수신한 뒤 커서를 확정하고, 중간 실패·취소는 다음 조회에서 안전하게 복구한다. 저장 순서와 eventId 중복 제거 규칙을 유지한다.
- `WorkflowRunView.jsx`: 이력 조회 중·실패·실제 빈 목록을 구분한다. 과거 애니메이션 생략을 기록 부재로 표시하지 않는다.

## 검증

- 관련 단위 테스트 **112개**, 격리 브라우저 테스트 **3개** 통과. ESLint·프로덕션 빌드·`git diff --check` 통과. 기존 대형 3D 번들의 크기 경고는 유지된다.
- 실제 React App·Dashboard·조회 훅을 사용하는 격리 Chrome에서 Run 선택과 결과물 화면 새로고침, 과거 기록 표시, 애니메이션 미재연, 로그인·회원가입·전자문서 뒤로/앞으로/닫기, 다른 계정 초안 분리를 검증했다.
- 기존 비로그인 초안 → 로그인 성공 복원, 로그인 실패·취소, JWT 없는 요청 차단, 작업 중단·답변 중복 방지 UI 검증을 유지했다.
- 기존 로그인 UI 테스트는 일정 시간 추측 대기 대신 실제 History 이동 완료 이벤트를 기다리도록 조정했다. 로그인·회원가입 취소 복귀를 실제 브라우저 이력으로 검증한다.
- 단위 검증은 선택 Run 삭제·다른 계정 후보 무시·신규 생성 후보, 과거 기록 여러 페이지·중간 실패 복구, 기존 이벤트·실행 상태·조회 재시도·인증 경계를 포함한다.
- HTTP 503 헤더 검증용 기존 Mock에는 명시적 실행 허용과 사용자 확인을 공급했다. 해당 Mock이 실제 HTTP 오류 경계까지 도달하도록 맞췄으며, 운영 전송의 승인 스위치·인증·명시적 확인 검사는 그대로다. 차단 조건에서 HTTP가 발생하지 않는 검증도 추가했다.
- 이번 점검은 목업 HTTP 응답을 사용한다. 실제 서버·Docker·유료 모델을 실행하지 않았다.
- 전체 프론트 테스트의 통과를 주장하지 않는다. 앞선 점검에서 `newAgentRunFlow.test.mjs`의 기존 생성 경로 테스트 2개 실패와 대기를 확인했으며, 해당 레거시 생성 경로는 이번 수정 범위에서 변경하지 않았다.

## 개발정의서 확인

화면 상태와 저장 후보만 수정했다. Host·Agent 역할, A2A/MCP 규격, 승인 Configuration, 불변 Artifact, 생성·제어의 멱등 처리, 실행 예산과 최종 판정은 변경하지 않았다. 서버 인증·프로젝트 소유권을 브라우저 저장 값으로 대신하지 않는다.
