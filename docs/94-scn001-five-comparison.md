쉽게 말하면, 코드 검토 경고를 끝내 고치지 못하거나 파일 편집에서 막힌 실행, 앱을 불러오지 못해 채점할 수 없던 실행, 실제 기능은 되지만 최종 보안 조건을 놓친 실행을 구분해야 한다. 보호 정책이 생성 후보를 막은 정적 경고와 독립 시험에서 재현한 실제 FAIL도 서로 구분한다. 중간에 빨리 멈춘 실행이 많으면 평균 비용·시간이 작아져도 완제품 생산성이 좋아졌다는 뜻은 아니다.

마지막 Multi Ver2 회차는 실제 FAIL 3개와 ERROR 6개가 섞였다. 유효한 가입 자체가 실패하면서 후속 데이터·보안 검사의 전제를 만들지 못한 경우가 포함된다. 그래서 해당 조건의 충족률을 확정된 단일 숫자로 쓰지 않고 범위로 표시했다. 47.6~66.7%는 관찰 3회의 요구사항 충족 가능 범위를 평균한 값이며 전체 5회 평균이 아니다.

## 실행 중단 이력

8번째 실행 뒤 운영 드라이버가 한 차례 멈췄다. 읽을 파일이 없거나 편집 대상·버전이 맞지 않은 모델의 파일 도구 호출 실패였고, 모든 도구 시도가 완료되어 결과 불명이 없음을 원장으로 확인했다. 8개 결과를 그대로 유지하고 원래 계획에서 아직 제출하지 않은 12개 슬롯만 이어서 실행했다. 실패 Run 재시도·대체나 에이전트 코드 수정은 하지 않았다. 인증·통신·무결성 차단 규칙은 유지했다.

## 비교 조건과 검증 범위

- 실제 요청: “이메일과 비밀번호로 회원가입 기능을 만들어줘.” 모델은 `gpt-4.1-mini-2025-04-14`, temperature는 0이다.
- Ver1은 개발 중 공통 보호시험과 결과를 제공하고, Ver2는 자체 시험으로 개발한 뒤 독립 최종 시험을 적용했다. 최종 시험은 네 조건 모두 동일한 9개 검사·7개 요구사항이다.
- 모델·시작 코드·승인 설정·기존 92번 보강 구현을 유지했다. 코드 수정이나 회귀 테스트 재실행은 하지 않았다.
- 기존 실험 ID와 회차 1을 유지하고, 실행 순서 5~20·회차 2~5를 추가했다. 짝수 회차는 조건 순서를 뒤집었다.
- 각 새 설정을 기존 조건별 승인 설정 및 공통 설정과 대조했다. Ver1·Ver2의 개발 중 보호시험 정책은 유지했다.
- 실행 시작·종료 구현 지문 일치: True.
- 모델의 작업 중단은 관측 결과로 남겼으며 동일 Run을 재개하거나 실패 표본을 교체하지 않았다. 인증·전송·무결성 오류는 중단 대상으로 유지했다.
- 기존 40회 실험은 이번 20회에 섞지 않았다. 이전 단회 결과 4개만 포함한다.
- 비밀값·원시 응답·로그를 공유 자료에 옮기지 않았다. 프로젝트 Git 커밋·푸시는 하지 않았다.
