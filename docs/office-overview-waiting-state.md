# 전체 직원 표시와 확인 대기 점검

## 화면 수정

- 작업 중인 직원에게 자동으로 카메라를 이동하면서 다른 직원·책상·소품을 숨기던 근접 촬영을 오피스에서 제거했다.
- 팀장과 네 작업 직원은 같은 전체 구도에 남는다. 직원 선택은 상태 표시만 바꾸며 다른 사람을 숨기지 않는다.
- 리더석이 사이드바에 가려지지 않도록 좌석 전체 크기에 여유를 뒀다. 모바일에서 넓은 장면의 중앙만 잘라내던 스타일을 제거하고, 인물 전체와 화면을 채우는 배경을 분리했다.
- 실제 `working` 상태인 직원의 이름표에 연두색 테두리와 약한 빛을 추가했다. 대기 직원의 몸·책상 투명도는 낮추지 않는다.
- 직접 카메라를 움직이는 `둘러보기`와 원래 구도로 돌아오는 `전체 보기`는 유지한다.
- 일반 화면의 `입력 대기`를 `확인 대기`로 정리했다. 추가 입력 부족으로 단정하지 않고 현재 작업이 잠시 멈췄음을 안내한다. 서버의 `WAITING_INPUT` 상태 자체는 변경하지 않는다.

## 실제 작업의 대기 원인

- 확인한 요청: `회원가입 하는 간단한 웹사이트`.
- Run과 Planner Step 모두 `WAITING_INPUT`, A2A Task는 `TASK_STATE_INPUT_REQUIRED`였다. 실제 모델 호출 이후의 상태다.
- 기획안 의미 검증 결과는 `HELD / SEMANTIC_EVIDENCE_UNVERIFIED`다. 검증 모델은 항목들을 `SUPPORTED`라고 응답했지만, 제시한 근거 인용을 확정된 요구사항 원문에서 확인하는 검증을 통과하지 못했다.
- 이 기록만으로 사용자 요청이 잘못됐거나 실제 요구사항 위반이 확정됐다고 판단할 수 없다. 기획 결과의 근거 인용·검증과 대기 사유 전달을 보완해야 한다.
- 현재 공개 Run·Step·Trace 조회 화면에는 A2A Task의 질문·의미 검증 사유가 연결되어 있지 않다. 그래서 기존 화면은 상태만 표시했다.
- 이번 화면 수정으로 보류를 해제하거나 검증을 우회하지 않는다. 실제 작업을 재개하거나 새 유료 모델 호출을 실행하지 않았다.

## 검증

- 프론트 테스트 198개, 빌드, ESLint 통과.
- 격리된 브라우저에서 단일 작업·품질/보안 병렬 작업·확인 대기·직원 선택·직접 둘러보기 모두 인물 5개와 이름표 5개가 유지됨을 확인했다. 모바일 390px·320px에서도 화면 안에 이름표가 표시됐다.
- 화면 검증 데이터는 브라우저 안에서만 대체했다. 실제 대기 원인은 저장된 실제 실행 기록에서 따로 확인했고, 실제 Run을 수정하거나 재개하지 않았다.
