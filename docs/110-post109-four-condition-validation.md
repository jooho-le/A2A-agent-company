# 110. 108·109번 보완 후 네 조건 실제 API 단회 비교

작성일: 2026-11-23. 요청은 네 조건 모두 **“이메일과 비밀번호로 회원가입 기능을 만들어줘.”**다. Single·Multi와 개발 중 공통 보호시험 제공·미제공을 교차해 **조건별 한 번, 총 4건**을 실행했다.

**Single Ver1·Single Ver2·Multi Ver2는 독립 최종 9개 시험을 모두 통과했다. Host의 전체 작업까지 SUCCESS인 조건은 Single Ver1이다. Multi Ver1은 도구 오류로 보류돼 제품을 평가하지 못했다.**

실행 중 구현·설정·평가 기준을 바꾸거나 생성 코드를 사람이 수정하지 않았다. 실패한 Run을 다시 제출하지 않았으며, 이전 실험과 표본을 합치지 않았다.

시간은 요청 접수 후 **Host가 종료하거나 보류할 때까지**다. 이후 독립 평가에 걸린 시간은 포함하지 않는다. Ver2의 574.894초·255.302초는 Host FAIL까지의 시간이며, 38.953초도 완성 시간으로 비교하지 않는다. 성공 판정 시간은 Host SUCCESS가 확인된 Single Ver1만 표시했다.

## 조건별 확인 내용

### Single Ver1 — 제품과 Host 모두 성공

등록 Source v1은 시작 규격 Build를 통과했다. 개발 중 공통 보호시험은 QA 6개·Security 3개가 모두 통과했고, 독립 최종 시험도 **9 PASS·0 FAIL, 요구사항 7/7**이다. 평가 Manifest의 Run·Source·버전이 일치한다. Host는 제품 수정 시도 없이 SUCCESS로 끝났다.

다만 자체 생성 시험은 모두 PASS가 아니었다. QA는 3 PASS·2 FAIL, Security는 0 PASS·2 FAIL·1 SKIP과 시험 수정 이력이 남아 있다. Ver1의 기존 공통 보호시험·충돌 판정 정책에 따라 최종 Host 결과가 결정됐으며, 원본 자체 시험 결과를 PASS로 고치지 않았다.

중간 모델 시도 6번은 **HTTP 500 / SERVER_ERROR**, 소요 69.738초, 사용량 미확인이다. 109번의 진단이 실제 호출에서도 상태 코드·공급자 유형을 구분했고, 기존 재시도 한도 안에서 다음 호출을 이어갔다. 이 실행의 총비용을 임의로 확정하지 않았다.

### Multi Ver1 — 파일 도구 오류 후 보류, 제품 미평가

Planner는 완료했지만 Developer가 `LLM_TOOL_EXECUTION_FAILED`로 실패했다. 도구 기록에는 `WRITE_CONFLICT` 1건 뒤 `FILE_NOT_FOUND` 2건이 있으며 모두 `resultUnknown=false`다. 알려진 실패이므로 전송 과정의 데이터 소실이나 결과 불명 쓰기로 해석하지 않는다.

등록 Source·Build·QA·Security 결과가 없어 독립 제품 평가를 수행할 수 없었다. 확인된 비용 $0.0280792와 보류까지 38.953초는 기록하되, 낮은 비용·빠른 제품 완성으로 비교하지 않는다. 이 기록만으로 파일 경로 선택 오류와 복구 안내 중 어느 쪽이 근본 원인인지까지 확정하지 않는다.

### Single Ver2 — 최종 제품은 통과, 자체 검증·수정 흐름은 실패

v1·v2 모두 시작 규격 Build를 통과했다. 마지막 v2는 독립 최종 시험 **9 PASS·0 FAIL, 요구사항 7/7**이며 평가 Manifest도 일치한다.

반면 개발 중 자체 QA는 통과했으나 Security 시험의 FAIL이 남았다. 마지막 Security 실행은 2 PASS·1 FAIL이었다. 두 번째 제품 수정 시도에서 `LLM_DEVELOPMENT_NO_PROGRESS`가 발생했고 Host는 FAIL로 끝났다. 도구 기록에는 `EDIT_TARGET_MISSING`과 `EDIT_STALE_READ`도 남아 있다.

따라서 **독립 시험 범위의 제품 통과**와 **자동 개발 절차의 성공**을 구분해야 한다. 자체 시험의 주장·관찰 방식·요구사항 연결이 독립 시험과 다른지 추가로 대조할 수 있지만, 이번 실행만으로 자체 시험을 오탐으로 확정하거나 무시하지 않는다.

### Multi Ver2 — Build 복구 후 제품 통과, 후속 수정에서 실패

v1 Build는 `SCN001_NAME_UNDEFINED`로 실패했고, 첫 수정 후 v2는 `SCN001_START_CONTRACT_OK`로 통과했다. v2의 자체 QA는 6 PASS·1 FAIL, Security는 시험 수정 후 3 PASS였다.

QA 이슈의 참조는 `test_signup_password_hash_policy`다. 이후 두 번째 제품 수정 시도에서 `LLM_DEVELOPMENT_NO_PROGRESS`가 발생했고 Host는 FAIL로 끝났다. 도구 오류는 `EDIT_TARGET_MISSING` 1건이다.

등록된 같은 v2의 독립 최종 시험은 **9 PASS·0 FAIL, 요구사항 7/7**, 평가 Manifest 일치다. 자체 QA의 해시 정책 검사와 독립 Security 검사 사이의 차이를 아직 원인 확정으로 쓰지는 않는다.
