# 93. 보강 후 네 조건 각 1회 실행 검증

작성일: 2026-11-23. 사용자 요청에 따라 Single/Multi × Ver1/Ver2를 각각 **1회, 총 4회만** 실제 OpenAI API와 기존 Docker 이미지로 실행했다. 별도 유료 예비 실행·실패 Run 재제출·10회 반복은 하지 않았다.

## 확인한 중단 원인

### 세 조건: 입력 검증 오류의 비노출 경고를 끝내 해소하지 못함

Multi Ver1, Single Ver1, Multi Ver2는 Developer의 `READY_SIGNUP_QUALITY_REVIEW` 경고 후 동일 위험이 남아 `REPEATED`로 중단됐다. 첫 두 실행의 남은 Source를 읽기 전용 AST로 점검했을 때 `DEFAULT_VALIDATION_MAY_ECHO_CREDENTIALS`가 남아 있었다. 일반 HTTPException 처리기는 있었지만, 프레임워크의 RequestValidationError 경로를 해결한 근거가 없었다.

이는 정적 위험 경고다. 등록된 Snapshot과 실제 독립 실행 증거가 없으므로 이 세 제품에서 노출이 실제 발생했다고 확정하지 않는다. 현재 완료 전 검토 경고가 제품 후보 등록 전에 실행을 끝내고 있어, Build·검증·제품 수정 순환으로 이어지지 못한다는 한계가 확인됐다.

### Single Ver2: 앱 진입 파일이 자기 자신을 import하는 잘못된 생성 코드

고정된 v1 `source.tar`의 `main.py`에는 `APIRouter`가 생성되어 있지만 `app`을 정의하는 대입은 없고, 85행에 `from main import app`이 있다. 자기 모듈에서 아직 정의되지 않은 app을 가져오는 구조다. 독립 평가의 실제 관찰은 9개 검사 전부 `APP_IMPORT_FAILED`였으며, 개별 기능 assertion의 FAIL은 아니다.

이번 승인 빌드 프로필 `scn001-compile`의 명령은 Python `compileall /snapshot`이다. 이 빌드의 성공만으로 앱을 import하고 실제 실행할 수 있다는 사실이 보장되지 않았다. 시작 코드의 진입점을 보존하고 import·시작 검증을 연결하는 보완이 필요하다.

## 실행 전 회귀 검사

1. 새 검사 5개 파일의 첫 묶음: 136개 통과, 2개 실패.
2. 실제 구현 누락 1개 수정: `checked_rejection()`의 허용 코드에 `READY_SIGNUP_QUALITY_REVIEW` 등록. 누락 상태에서는 엔진이 새 경고를 정상적인 교정 요청으로 처리하지 못했다.
3. 테스트 입력 보정 1개: 읽기 내용 축약 검사는 축약이 이득인 충분한 길이의 합성 본문으로 검사하도록 변경했다. 작은 본문을 그대로 반환하는 기존 최적화는 유지했다.
4. 관련 통합·회귀 묶음: **246개 통과, 1개 실패**. Security의 ID 교정 성공 경로가 HUMAN_REVIEW로 끝난 사례다.
5. 해당 실패 항목 단독 재검사: **1개 통과**. 초기 실패의 원인은 확정하지 못했다. 전체 묶음이 모두 통과했다고 합산하거나 이 불안정성이 해결됐다고 표시하지 않는다. 후속 실패에서 단계와 Trace 유형을 확인할 수 있도록 assertion 진단을 추가했다.

변경 전·후에 각각 의미가 있는 검사를 실행했으며 유료 비교가 시작된 뒤에는 `src/`·스키마 구현을 수정하지 않았다. 실행 시작·종료의 구현 지문이 일치함을 확인했다.
