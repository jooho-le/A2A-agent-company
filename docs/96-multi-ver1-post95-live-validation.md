## 실제로 작동한 부분

- Source 검토는 6번·9번 모델 호출 뒤 각각 교정을 허용했고, 14번 호출 뒤 기존 교정 한도 소진으로 중단했다.
- 모델 입력 기록에는 7→8번, 10→11번의 읽기·수정 요구가 남았다. 실제 MCP 읽기와 편집·쓰기도 실행됐다.
- 편집 대상 조각이 없는 `EDIT_TARGET_MISSING`이 1회 있었다. 미적용이 확정된 오류로 처리한 뒤 12→13번에서 새 읽기와 쓰기로 복구했다. 결과 불명 쓰기를 재전송한 것이 아니다.
- 도구 시도 11개는 모두 종료 기록이 있고 결과 불명은 0개다. 기존 인증·경로 권한·해시 확인을 유지했다.
- 최종 원인은 JSON 오류로 기록되지 않고 Source 수정 소진으로 구분됐다.

## 남은 원인

종료 시 실제 작업 폴더의 Source를 실행하지 않고 AST로 확인했다. 남은 경고는 `DEFAULT_VALIDATION_MAY_ECHO_CREDENTIALS` 1개이며, 공개 REQ-006에 연결된 `main.py`의 가입 입력 경로다.

`main.py`에는 일반 `HTTPException` 처리기가 있었지만, 입력 검증 오류를 담당하는 `RequestValidationError` 처리기는 없었다. 모델은 파일을 고쳤어도 보호해야 하는 오류 경로를 정확히 선택하지 못했다. 현재 지시가 실제 모델에게 올바른 예외 종류와 수정 위치를 충분히 연결하지 못한다는 한계가 드러났다.

이는 정적 위험 경고가 남았다는 관찰이다. 등록 Snapshot과 독립 실행 근거가 없으므로 이번 제품에서 비밀번호 노출이 실제 발생했다고 확정하지 않는다. 정적 시작 검사에 남은 경고는 없었지만, 앱 실행 Build에 진입하지 않았으므로 실제 시작 성공으로 표시하지도 않는다.
