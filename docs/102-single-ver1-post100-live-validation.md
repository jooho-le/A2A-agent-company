## Single로 실행됐는지 확인

- 실행 설정의 Agent 서버는 `SINGLE_AGENT` 하나다.
- 모든 LLM 사용량 기록의 실행 주체는 `SINGLE_AGENT`다.
- 저장된 Agent Context는 `single_agent`의 1개이며, 모든 Workflow Step이 같은 실제 Agent Context ID를 사용했다.
- Workflow에는 기획·개발·QA·Security라는 업무 단계 이름이 남지만, 이를 수행한 Agent는 하나다. Multi처럼 역할별 Agent 서버 4개를 실행한 것이 아니다.

## 101번 Multi Ver1과 비교 — 각각 1회

두 실행의 자연어 요청·모델·LLM 한도·시간 한도·Tool 설정·이미지·보호시험 파일·가격표·구현 파일 SHA-256이 같다. 시작 Source의 Repository·Commit·Tree·Snapshot·Lock 해시도 동일함을 대조했다.

| 지표 | Single Ver1 · 102번 | Multi Ver1 · 101번 |
| --- | --- | --- |
| Host 판정 | SUCCESS | SUCCESS |
| 최종 9개 시험 | **9/9 PASS** | **9/9 PASS** |
| 요구사항 충족 | 7/7 | 7/7 |

**이번 단회 관찰에서는 Single의 성공 판정 시간이 짧고 수정 횟수가 적었다.** 이를 일반적인 구조 우위로 단정하지 않는다. Multi에는 사용량 미확인 공급자 오류 1회와 시작 오류 수정 2회가 있었고, Single에는 시작 오류 수정 1회가 있었다. 이런 실행별 차이도 시간·비용에 들어간다. Multi의 비용 하한을 전체 비용으로 평균내거나 정확한 비용 차이를 계산하지 않는다.

이 표는 각 조건 한 번의 실제 관찰이며 반복 평균·성공률 추정·4조건 전체 비교표가 아니다. 이전 구현의 94·96·99번 결과를 이 판본의 반복 표본으로 합치지 않는다.

## 검증 한계

1. **자체 생성 시험은 별도 문제다.** Agent 보고서의 QA 생성 시험 5개는 FAIL이고 QA 보호시험 6개는 PASS다. Security 보고서의 요구사항 결과 3개도 FAIL로 남아 있다. Host는 실행 전에 정해진 Ver1 보호시험 우선 규칙으로 판정했고, 독립 최종 9개도 통과했다. 자체 생성 시험까지 정상이라고 고쳐 기록하지 않는다. 보호시험이 없는 Ver2는 아직 확인하지 않았다.
2. **시간 지표를 섞지 않는다.** 187.735초는 Host SUCCESS까지의 시간이다. 최초 통과 Snapshot 산출 시간(TIME-05)은 앞선 후보의 평가가 확정되지 않아 `EARLIER_PASS_UNVERIFIED`다. 최초 Build PASS나 Host 성공 시간으로 임의 대체하지 않는다.
3. **전체 기록의 비노출은 미완료다.** 별도 Run 기록 비노출 검사는 수집 범위 부족으로 UNVERIFIED, 추적 검사는 PASS다. 제품 비노출 시험 PASS만으로 전체 Agent 출력·기록 보안을 보장하지 않는다.
4. **보조 정적 검사도 구분한다.** REQ-003의 정적 판정은 UNVERIFIED다. 독립 실행 판정 PASS와 함께 보존하고 정적 검사를 완료로 표시하지 않는다.

## 개발정의서·실행 조건 점검

- Orchestrator의 판정 책임, Single의 연속 Context, 단계별 MCP 권한, 불변 Snapshot·실제 Build·독립 평가를 유지했다.
- 모델·Tool 각 200회, 실행 1,200초, 총 토큰 2,000,000, 단계별 출력 교정 2회·공급자 재시도 1회의 동일 한도를 사용했다. 코드 수정 한도를 늘리지 않았다.
- 기존 Ver1 보호시험·최종 시험·요구사항·A2A·Artifact 규격·가격표·승인·인증·Sandbox를 변경하지 않았다.
- Run 제출은 정확히 1건이다. 구현의 실행 전후 해시가 일치하며, 같은 판본인 101번 Multi의 구현 해시와도 일치한다.
- `.env`·사용자 설정·이전 실험·등록 Source를 수동 수정하지 않았다. 프로젝트 Git 커밋·푸시는 하지 않았다.
- 종료 후 실험 Host·Agent 포트 18002·18101~18104와 Docker 컨테이너가 남지 않음을 확인했다. 기존 Docker 데몬은 유지했다.
- 원본·Source v1~v2·실행 영수증·Trace·전체 평가 결과는 `.data/experiments/scn001-single-ver1-post100-20261123/`에 보존했다.
