프로젝트의 A2A 클라이언트와 Agent 서버를 실제로 연결해 통신 경계를 확인합니다.

진단 서버 확인 중Orchestrator 중계 → Agent 수신 → 결과 반환
이 화면에서 확인하는 것: 전송·수신 데이터 일치, 지정 필드의 근거 대조, 구간별 실측 시간입니다. 실제 LLM을 호출하지 않으므로 실제 모델의 할루시네이션 여부는 미검증입니다. 모든 수치는 이 진단 실행에서 측정하며, 설정한 지연은 따로 표시합니다.

실제 합성 요청서·요구사항·검수 기준 펼쳐 보기
멀티: Planner 결과 → Orchestrator → Developer → Orchestrator → QA·Security 병렬. 역할 간 결과는 중계하며, upstreamHash로 앞 단계 결과가 그대로 들어왔는지 대조합니다.

전달 오류와 응답 오류를 구분입력 자체가 100→101로 바뀐 경우와, 100을 받고 101이라고 주장한 경우를 서로 다른 항목으로 표시합니다.
시간은 같은 단조 시계로 실측진단용 서버를 한 프로세스의 서로 다른 TCP 포트에 띄웁니다. 전달 시간에는 HTTP·대기가, 결과 확인에는 저장·폴링이 포함됩니다.
프로덕션과 분리된 실험일회용 DB와 인증된 진단 Agent를 사용합니다. API 키·Docker·실제 소스코드 작업 없이 통신만 확인하며, 최대 5회·전체 45초로 제한합니다.
